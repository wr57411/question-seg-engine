## 3. OCR 适配算法逻辑（现状产线）

- **MCP 通道只拿回文本**：`tools/call paddleocr_vl`，`output_mode:"simple"`、`return_images:false`
  （ocr-lib.ts:163-166）⇒ **坐标、置信度、表格、公式、版面全部丢弃**（`prunedResult` 整层没读）。
- **行坐标 = 摊字符猜**：整页 OCR 无位置 ⇒ hardNorm 保留字符下标映射 → 每个解析块文本在整页文本里
  单调前向匹配（锚点链）→ 未匹配片段=洞 → 洞按列/视觉行/行内 x 排序 → 字符按洞宽比例分配。
  两处实测串位后宽度比仍合格（判据抓不住）——注记于 ocr-page-fill.ts:292-297、345-354、425-434。
- **两条注入路径**（export-stages.ts）：
  - 路径 A（items）：只补「题号形态」的行，判重按同页同号（不用绝对 y，跨源坐标系差 ~3 倍）；
  - 路径 B（fullText）：补整行漏识别，只收答案条目/题号独占一行，定位=下一行锚块上方；
    页尾裸题号插到最右栏 y 最大块下方。
  - 融合作品跳过两条注入（跨源判重失效）。
- **corrections**（切题前应用，显式清洗）：replace(O→0，只换紧跟点/角的)、replace_text、
  split（拆块救题号在行中）、insert（图注插最近图片后 / body-hole 按 y 插阅读顺序）。
  台账三态：missed / unverified（63 条未核）/ disabled。
- **置信度字段全链路未用**：MinerU `_model.json` 的 score、layout.json span score、Paddle 行框 rec_scores
  已能拿到但没有任何消费方（formula-five-audit 只用了公式 score）。

### 4.3 已评估工具定位与禁区（防重复挖，全文见 docs/BACKLOG.md N-01~N-10、§106-§108）

- 主上游 **MinerU pipeline**（不变）；OXR=第二解析源；夸克 Word=对账主尺（0 token）；
  MiniCPM=结构+表格文本交叉源（决策 A 收口）；PaddleOCR-VL-1.6=文字最准（公式 0 真错）+ 行对齐「字」来源；
  PP-StructureV3=独立结构计数器（table 13/13 册全等，可当独立分母）。
- **禁区**（每条已证伪，勿再挖）：vlm 换源（行结构 63→14）；AI 逐页抄金标（200 万 token）；
  出处残片判据（误报>90%）；Word 第X章切章；「原书缺题」归因；题号被切走的通用规则（两次形状扫描证伪）；
  加严题号正则（§97 已覆盖）；跨页泄漏修法；Jev 整题级评分（AUC 0.582）；MiniCPM 公式专项（样本太小）；
  实验区按小问切题（用户否决）；语义融合（节内重号选错）；**经 MCP 拿 VL/V3 结构坐标**（prunedResult 被 MCP 丢弃）；
  同步 layout-parsing 进产线（慢 3.2× 且将下线）；拿 MinerU score 当公式质量门（I_保 0.9442 反例）；
  厂商榜单数字当结论（96.33% 未独立验证）。

### 8.1 ⚠️ 探针副产物：发现生产代码缺陷（`cleanOcr` / `cleanOcrLines` 误删正文）

> **2026-11-05 已修复**（B-33 `DONE`，check 554/554 绿）：剥标签改白名单（`KNOWN_HTML_TAGS`/`HTML_TAG_RE`，
> 单一权威源 `scripts/ocr-lib.ts`；白名单外宁残留不误删），`cleanOcr`/`cleanOcrLines`/`stripMarkup` 三处同源。
> A/B 实测找回 234 字符、4 个关键正文样例全找回、老行为零破坏。下文保留**修复前**的量化记录。

**现象**：`cleanOcr` / `cleanOcrLines`（`scripts/ocr-lib.ts:41-62`）用 `<[^>]+>` 剥 HTML 标签。
理科试卷的**不等式公式** `$ r<R $` 里含 `<`，一旦同一段后面出现任意 `>`（后一个不等式、`<table>` 等），
`<R $ … 所示 <table>` 会被整体当标签删掉。

**实测**（`tmp/a3-probe/mcp-vl.md`，真实 MCP 输出 3140 字符）：

| 清洗方式 | 结果长度 | 中文正文损失 |
|---|---|---|
| 现有 `cleanOcrLines` | 1126 字符 | — |
| 安全剥离（只删已知标签名） | 1366 字符 | **240 字符 / 16 处中文被误删** |

被删样例：`开关后，将滑动变阻器`、`端滑动，下列说法正确`、`C. 电源输出的功`、`D. 电源内阻消耗`、`2[人教版必修三`。

**影响面**：`cleanOcr` 用于区域裁图 OCR（`scripts/ocr-fill.ts`）、`cleanOcrLines` 用于整页 OCR
（`scripts/ocr-page-fill.ts`）⇒ 补行文本可能在清洗阶段就已残缺，**且无记录**（踩红线 1「不静默失败」）。
镜像问题：支线 `scripts/paddle-line-align.ts:73-78` 的 `stripMarkup` 同样用 `<[^>]*>`，先剥标签再过滤符号，
顺序救不了——它也受影响。

**正确做法（未实施）**：只删**已知 HTML 标签名**（`div|table|tr|td|th|p|span|br|img|…`），
或先保护 `$…$` 公式区间再做标签剥离。修它=改数据清洗，须显式决策 + A/B（候选数/消费率/题数三项回归）。
已登记 `docs/BACKLOG.md` **B-33**。
