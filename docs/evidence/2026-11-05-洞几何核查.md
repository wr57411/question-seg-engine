## 1. 结论：**维持不接线**，方向更正

1. **`blocks` 层确实有膨胀块，而且模式很集中**。全册 162 个与洞行带同栏重叠的块（三源并集）里，
   4 块 `inflation ≥1.4`：p27 1.47、p91 **3.01**、p150 **2.62 / 2.36**。四块都是
   「`N. X 必刷知识/考点·…`」这类**题号 + 栏目标签行**，bbox 宽 230–232pt，块内真实墨迹只有 77–158pt。
   ⇒ 交接段的「230pt vs 墨迹」**找到了对应对象**。
2. **但不是所有洞都是它造成的**。112 洞里只有 **p91 h1** 同时满足「洞内墨迹只占该行 48%」+
   「同行有 3.01 膨胀块」⇒ 判 `FRAGMENT`（半真洞）。p150 h0 是 0.50（正好在阈值边界）、
   p150 h2 是 0.87 ⇒ 按最严 AND 判 `REAL`。**「p150 三洞都是假洞」这个说法过强，不成立。**
3. **洞的横向是完整的，问题在纵向/墨迹占比**。全册 `洞宽 / 行宽` 落在 **0.96–1.00**，
   即洞横向覆盖整行；差异体现在「洞内墨迹 / 该行墨迹」= **0.18–1.00**。
4. **V3 行框落位另有一个独立问题**。与原卷墨迹做互相关：p91 **−6pt**、p150 **+5pt**、
   p159 **+3pt**（墨迹命中 +7.25% / +15.81% / +8.26%），p74 ≈0。方向大小逐页不同，
   不能靠一个固定偏移修。

   有一条就是 MCP 那 2 条碎片合成的正确整行，数量不可直接相比。

⇒ **维持不接线**（`daily` 默认行为零变化不变）。批次 3 原定「标题块 bbox 膨胀核查」**已完成**，
结论是「膨胀块存在、但只解释了一部分洞」；下一轮方向见 §8。

## 2. 方法：独立来源与度量定义

- **独立来源**：`pdftoppm -gray -r 150 -f N -l N -singlefile origin.pdf` → PGM，复用生产脚本的
  `parsePgm` / `INK_THRESHOLD=160`。单页约 0.25s，全册 49 页秒级。
- **被检验对象**：`stages.json` 的 `uncovered`（洞）与 **`blocks ∪ raw ∪ discarded`**（块）。
  ⚠️ 框集必须与 `uncovered` 的定义同源（`export-stages.ts` 的 `computeInkCoverage` 用这三层并集）；
  只取 `raw` 会漏掉 230pt 级膨胀块——第一版就是这么错的（§5.2）。
- **真实行**：`inkLineAround` —— 以洞为锚点、在**洞的 x 范围**内向上/下扫到 3pt 白缝为止，
  得到该行完整 bbox 与墨迹像素数。不用全局切行（`splitInkLines` 在窄 x 范围会多切少切，
  实测算出过「洞宽是行宽 1.99 倍」的自相矛盾值）。
- **四组量**：`holeInk`（洞内墨迹）、`bandInk`（真实行 bbox + 墨迹）、`holeToBandWidth`（洞宽/行宽）、
  `inkShare`（洞内墨迹/行墨迹）、块的 `inflation = 块 bbox 宽 / 块内真实墨迹宽`（`dx/dy` 只记录）。
- **判定三态**：`FAKE`（洞内无墨；因 `uncovered` 定义，结构性不可达）/ `FRAGMENT`（洞宽/行宽 <0.5
  **或** 墨迹占比 <0.5，**且**同源框集里有 `inflation ≥1.4` 的块）/ `REAL`（其余）。
  **`REAL` 只表示「洞对应真实墨迹、且未见膨胀块吃掉该行」，不等于「该补字」。**
- **位移**：`bestVerticalShift` 对 V3 行框做整页纵向互相关，搜索限 **±8pt**（半行距内；
  放宽到 ±20 时 p74 会出现 −18pt 的「错一行」假峰，已用单测锁住）。

复现：

```bash
npx tsx scripts/audit-hole-geometry.ts --pages all --sensitivity
node --import tsx --test tests/audit-hole-geometry.test.ts
```

## 5. 假设的证实与边界

### 5.1 逐条判定

| 子命题 | 结果 | 证据 |

| `blocks` 层存在 230pt 级膨胀块 | **成立** | 4 块，inflation 1.47–3.01，全是「题号+栏目标签」行，bbox 230–232pt vs 墨迹 77–158pt |

| V3 行框落位有系统偏移 | **成立** | −6 / +5 / +3pt，墨迹命中 +7%~+16% |
| 「洞里有墨迹」可当证伪证据 | **不成立（同义反复）** | `uncovered` 定义就是「有墨但不在任何 bbox 内」；已降级为「定义使然」 |

### 5.2 第一版为什么错（保留记录）

第一版只遍历了 `page.raw`，`raw` 里那 4 个 230pt 块不在（它们在 `blocks`），于是得出
「69 块无一膨胀 ⇒ 原假设证伪」。子代理复核时按 `uncovered` 的同源框集重算，直接量出
p91 3.01 / p150 2.62 / 2.36，结论反了。**教训**：判据的**分母/框集必须与被检验对象的定义同源**，
否则「没找到」会被误读成「不存在」（项目 L7「产物不是事实」的同类变体）。
第二版又踩了一次 `band` 口径：用「洞高×1.5 窗口内全部墨迹」，跨行把相邻行算进来，
p150 h0 算出「洞宽/行宽 = 1.99」的自相矛盾值；改用 `inkLineAround`（以洞为锚点扩到白缝）后才稳定。

## 6. 对抗性审查：结论哪里可能不准

1. **半真洞计数不稳**：阈值 ±20% 会让 `FRAGMENT` 从 0 变到 2 ⇒ 只能说「存在半真洞、p91 h1 是确证案例」，**不能报「恰好 1 个」**。
2. **`inflation` 对「框吞邻行墨迹」不敏感**：若膨胀块把相邻行也包进 bbox，分母（框内最宽墨迹行）会被撑大，inflation 反而趋近 1（230/234≈0.98）——恰对最有害的膨胀失明。本轮的 4 个膨胀块分母只有 77–158pt，不属于这种，但换书需重查。
3. **`bestVerticalShift` 只证「有偏移」，不证「偏移是主因」**：最大化框内墨迹 ≠ 严格对齐；且未回跑 jobs 验证「对齐后候选数上升」。
4. **对齐只有 4 页有 V3 缓存**，其余 45 页无 align 数据，不能外推全册。
5. **只覆盖 1 本（答案册-合订本）**，不覆盖其它 12 本的版式差异。
6. **`REAL` ≠ 该补字**：该不该补还取决于是否重复、是否装饰、补进去会不会错位，本轮不判。
7. **`FAKE` 结构性不可达**：`uncovered` 定义保证洞含墨，所以 `FAKE 0` 不是「测出来的胜利」，已在 §5.1 降级。

## 7.5 归因更正（2026-11-06 接管会话）：膨胀块是 OCR 注入块，不是 MinerU 块

接管会话按 §8.1「先查 blocks 归栏/合并逻辑」溯源时发现：§1.1 / §5.1 / 交接段把膨胀块归因给
「MinerU 标题块」**错了**。证据链：

- **4 个膨胀块全部 `ocr:true`**（stages.json 实测 p27 / p91 / p150×2）——是 `injectOcrFullTextLines`
  （fullText 路径）注入的 OCR 候选块，不是 MinerU 块。
- **MinerU 自读的同类行不膨胀**：p91「4. AD必刷知识·电容器」bbox [279,401,371,409] = 92pt 正常。
- **layout.json p91 根本没有「1. C 必刷知识·电容器」这行**——MinerU 的真实角色是**漏识别该行**（洞的来源），不是膨胀的来源。
- **真实机制**：fullText 路径合成 bbox 时 **x 范围直接继承锚点块**（`scripts/export-stages.ts:964`
  `[target.bbox[0], …, target.bbox[2], …]`）：「题号+标签行」墨迹 77–158pt 被拉成 ≈锚点宽 230pt。
- **连带更正**：修膨胀**不改变洞**（洞由 MinerU bbox+墨迹决定；注入块 y 带与洞 y 带错位、基本不遮挡墨迹），
  也**不解决配对 8/14**（`matchLinesToHoles` 的行集是 OCR 行框，不是注入块）。
  修膨胀改善的是**展示层候选块渲染真实性（`?ocr=1`）、hole-geometry 审计判据、产物可信度**。
- **修法探索（未实施）**：`emWidthOf(line)×fontPt` 估计实测 0.72–1.42，达不到 ≤1.2 判据（否掉）；
  候选方案=墨迹量测（锚点上方行高带内量有墨列范围，量不出回退锚点继承并记 `bboxSource`），未拍板未实施。
