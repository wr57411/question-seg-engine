# 对比模式字号校准——回原卷图像取地面真值

> 📍 交接导航：本文件是**测量证据（历史数据，非当前状态）**——被 `DECISIONS.md` 引用为口径依据。
> 当前状态、未闭合风险与红线见 **[docs/HANDOFF.md](../HANDOFF.md)**；通用约定见 **[AGENTS.md](../../AGENTS.md)**。


**任务**：不再用 bbox 推 bbox，直接在原卷页图 PNG 上量**真实墨迹**，判定 MinerU 行 bbox 是否紧贴墨迹，并据此裁决 A（0.92）/ B（1.06）两位分析者的系数分歧。

**结论先行**：

1. **bbox 紧贴墨迹**（总横向内边距中位 1.58pt ≈ 行宽的 0.7%，纵向 0.48pt）。**"bbox 偏宽污染了 B 的估计" 这个假设不成立。**
2. **真实字号**（纯 CJK 正文）`S_ink = inkW/N` 中位 **11.29pt**；现行字号中位仅 **7.92pt** → **偏小约 30%**。
3. **定案系数 `c ≈ 1.03`（因子 k ≈ 1.43）**。**A（0.92）错**（偏低 ~11–12%）；**B（1.06）接近但偏高 ~3%**；严格来说两者都不是点估计。分歧的真正来源是**样本构成**，不是 bbox 内边距。
4. **标题是独立层级**（~1.5–1.9× 正文），但按 bboxH 逐行推导已自动复现，无需额外层级表。
5. **垂直方向没有问题**：按 c=1.03 渲染，浏览器墨迹高只比原卷高 **~2%**。**"宽度对齐与高度对齐不可兼得" 这个前提是错的**——对 CJK 正文二者可以兼得（且用 c=c_ink 时渲染宽永远 < bbox 宽，连溢出都不会新增）。

## M1 bbox 紧不紧 —— **紧贴墨迹**（前提成立）

主体样本（n=125，阈值 128），单位 pt，正数 = bbox 比墨迹大：

| 边 | p10 | **p50** | p90 | mean | sd |
|---|---|---|---|---|---|
| dL = inkX0 − bboxX0 | 0.477 | **1.269** | 2.285 | 1.407 | 1.071 |
| dR = bboxX1 − inkX1 | −0.330 | **0.104** | 0.933 | 0.263 | 0.660 |
| dT = inkY0 − bboxY0 | −0.412 | **0.354** | 1.123 | 0.329 | 0.652 |
| dB = bboxY1 − inkY1 | −0.969 | **0.122** | 0.916 | 0.043 | 0.717 |

- **总横向内边距** `dW = dL+dR`：p50 = **1.58pt**、p90 = 2.78pt。
- 相对量 `dW / inkW`：p50 = **0.70%**、p90 = 1.80%。
- **总纵向内边距** `dH = dT+dB`：p50 = **0.22pt**。
- 对照（含 ASCII 行，n=552）：`dW/inkW` p50 = **0.84%**、`dL` p50 = 1.275 —— 同样紧。

**判读**：bbox 是**紧贴墨迹**的。唯一的小系统性偏差是**左边**多出 ~1.27pt（≈0.11em，等于 CJK 字形的左侧边距；bbox 左沿 ≈ 文字笔位起点），右/上/下几乎为零。总计 **<1% 的行宽**。

**关键推论**：**bbox 宽度可以放心当目标宽**；"B 的宽子集被 bbox 偏宽污染" 这一猜测**不成立**（bbox 只比墨迹宽 0.7%）。阈值敏感性：c_ink 在 thr=100/128/160 下为 1.026 / 1.029 / 1.032，**极稳**。

## M3 定案系数 —— **c ≈ 1.03（因子 k ≈ 1.43）**

**定义**：要让重建文字宽 = 原卷墨迹宽，需 `F_req = S_ink = inkW/N`（纯 CJK 浏览器 advance = 1em/字，故 advance 宽 = N·F）。建议系数 `c = F_req / bboxH`（现行 `F = 0.72·bboxH`，故因子 `k = c/0.72`）。

| 口径 | c（中位） | 因子 k | 说明 |
|---|---|---|---|
| **c_ink = S_ink/bboxH**（advance 宽 = 墨迹宽） | **1.029** | **1.429** | p10 0.931 / p90 1.154 / sd 0.089 |
| 同文本浏览器墨迹宽 = 原卷墨迹宽（最严） | **1.041** | 1.446 | 逐行用 `measureText` 的墨迹宽 |
| c_bbox = (bboxW/N)/bboxH（B 口径） | 1.038 | 1.442 | 与 B 的 pureCJK 1.428 一致 |
| 无标点 N≥8（≈A 口径） | 1.044 | 1.450 | |
| 无标点 N≥4（纳入短行） | 0.976 | 1.356 | 短行把它拖低 → A 的来源 |

- 现行字号 `F_cur = 0.72·bboxH` 中位 = **7.92pt**；需 `F_req` 中位 = **11.29pt** → 现行**偏小 30.0%**（`F_cur/F_req = 0.70`）。
- `c` 与 canvasW 无关：`c = (S_ink/pageW·cw)/(bboxH/pageW·cw) = S_ink/bboxH`，故 **760 与对比模式的 460（PANE_W）用同一系数**。

### 裁决

| | 因子 | 建议系数 | 与真值(1.43 / 1.03)偏差 |
|---|---|---|---|
| A | 1.317 | 0.92 | **偏低 ~11–12%** ❌ |
| B | 1.473 | 1.06 | 偏高 ~3% ⚠️ |
| **本次墨迹真值** | **1.43** | **1.03** | — |

**明确回答：A（0.92）错；B（1.06）接近但略偏高；正解 ≈ 1.03（区间 1.02–1.04）。**
**分歧的真正根源不是 bbox 内边距（bbox 只有 0.7%），而是样本构成**：
- A 用了含短行（N<8）的窄子集 —— 短行把中位拖到 ~1.36；A 的算术 em 表又叠了一层偏差 → 1.317。
- B 用了含大量 ASCII/公式块的宽子集 —— 那些块 bboxH 与宽的关系不同、ratio 偏高 → 1.473；B 自己的 pureCJK 子集其实就是 **1.428**，与真值一致，只是没把它当结论。
- 纯 CJK 正文真值 = **1.43**（两种独立口径 1.429 / 1.446 互证）。

## M5 垂直保真 —— **不会出问题**

浏览器实测（canvas `measureText` 的 `actualBoundingBoxAscent/Descent`，字号 200px，用**主样本每行真实文本**）：

| 字体 | 浏览器行墨迹高 em | 原卷 `inkH/S_ink` | 垂直比（浏览器/原卷，按 F=S_ink） | 浏览器行墨迹宽/字 em |
|---|---|---|---|---|
| "Songti SC"（stages.css 首选） | **0.961** | 0.938 | **1.023** | 0.994 |
| "STSong" | 0.950 | 0.938 | 1.016 | 0.994 |
| "Noto Serif SC" | 0.960 | 0.938 | 1.023 | 0.994 |

- 单字 `国` 墨迹高：Songti SC 0.894em、STSong 0.925em；**整行 8 字** 0.94em（行内混合字形取最大）。
- 关键：原卷 `inkH/S_ink = 0.938`，浏览器**整行**墨迹高 = 0.961em（Songti SC）→ 若令 `F = S_ink`，浏览器墨迹高 / 原卷墨迹高 = **1.023（+2.3%）**。
- **结论：水平对上时，垂直只高 ~2%（p10 0.97 / p90 1.09），在噪声内。不存在"水平对了垂直就错"的系统性问题。**
- **"宽度对齐与高度对齐不可兼得" —— 对 CJK 正文这个前提是错的。** 真正需要权衡的是别的：
  - 用 `c = c_ink`（advance 宽 = 墨迹宽）时，**渲染宽恒 < bbox 宽**（因 `inkW < bboxW`），**不会新增任何溢出**——比 B 的 k=1.475（会引入 ~32 对文字重叠）更安全。
  - 若改用 `c = 1.041`（墨迹对墨迹），字会再大 1%，收益（+1% 高度）可忽略。

## 与 A、B 两位结论的矛盾（直说，不调和）

| 议题 | A | B | 本次墨迹真值 | 判定 |
|---|---|---|---|---|
| 校准因子 | 1.317 | 1.473 | **1.43** | **A 错（低 11–12%）；B 略高（+3%）** |
| 建议系数 | 0.92 | 1.06 | **1.03** | 同上 |
| 字号偏小幅度 | ~24% | ~32% | **~30%** | 接近 B |
| 根因归因 | 严格 CJK 子集 | bbox 宽目标 | **样本构成**（非 bbox 内边距） | 二者都未点中 |
| bbox 是否紧 | （未测） | 隐含假设紧 | **实测紧（0.7%）** | 假设成立 |
| 宽度/高度冲突 | 未提 | "宽高不可兼得" | **可兼得（~2%）** | **B 的冲突判断过强** |

**一句话**：**A 低估修正量（子集太窄且含短行噪声），B 略微高估（子集太宽含 ASCII/公式）；真值是 1.43 / c≈1.03，B 基本正确、A 明显偏低。**

## 决策建议

1. **`stages/stages.js:222` 常数 `0.72 → 1.03`**（`fontFromLineHeight` 与 `baseFontOfPage` 共用同一常数，一处改全改）。
   - 保守区间 1.02–1.04；若想同时略补垂直的 +2%，取 1.04 亦在噪声内。
2. **不要动 `baseFontOfPage` 的公式行补丁**（含 `\frac` 行的 bbox 高仍会被撑大，补丁必要）。
3. **无需新增层级表**：按行 bboxH 推导已自动复现正文/栏头/标题三级。
4. **无需为溢出加兜底**：`c = c_ink` 下渲染宽恒 < bbox 宽，B 所担心的"放大后新增重叠"不会出现（B 的 32 对溢出源于其 k=1.475 比真值大 3%）。
5. **若坚持"单字符也精确"**：注意短行（N<8）与含 ASCII 行的 per-char 关系不同（M4 的 12–14pt 假峰即由此而来），但它们不是正文，可按现状处理。
