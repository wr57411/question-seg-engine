## 2. 机制：槽位怎么对齐、为什么不判对错

只有 **MinerU span** 与 **StructureV3 逐条框** 能当位置锚（其余三家只到块级）。
把块级源也拉进 IoU 聚类会产出假分歧——第一版实测把「四家都是 `I=q/t`、V3 是 `1/R_总=…`」
凑成同一槽位。因此改成两段：**hard 定槽位，pool 按同页文本归队**；
`canonLatex` 抹平格式差（`\,` / `\ ` / `\text{}` / 字符级空格 / 题号 `(2)`），
`mergeable`+`spans` 把"切宽切窄"归成同一阵营（实测 157 条属此类，**不算分歧**）。

**工具不选边**：同位出现 ≥2 种写法就整行标待核，`⚡` 只表示"两个逐条框家互斥"（位置可比、优先看）。
理由：只有一个 hard 家时它天然成基准，据此判页级家错是假权威——`910 Ω` 那行就是这么把读对的
MinerU/MiniCPM 判成离群、把挂错格的 VL/OXR 判成多数（已被页图推翻）。

读数：槽位 245；待核 35（其中 hard 互斥见 CSV）；粒度/切分差 157。

## 4. 结论：按你要公式的哪一面来选

1. **要正确的 LaTeX 文本** → **MiniCPM-OCR 与 PaddleOCR-VL 并列最好**（本轮 0 错），OXR 内容也对但
   汉字下标常落在 `$` 外（`P电=UI`、`I²Rt` 用上标字符），**结构信息为 0**。
2. **要"这条公式在页面哪个位置"** → 只有 **StructureV3** 给逐条公式框（MinerU 也给，但它内容错得多）。
   VL / MiniCPM / OXR 只能到块级 ⇒ 想做**位置级**交叉核对，V3 是唯一的源。
3. **表格里的公式** → MiniCPM 最干净（`$P_{电} = UI$` 五格齐）；VL 文本对但**会丢格子**
   （实测 `P_热=I²R` 整格没进表）；V3 **单元格顺序乱**；MinerU **乱码**（`P_{\oplus}`、`P_{\#}`）。
4. **MinerU 的 `score` 不能当公式质量门**：`I_保` 那条错得最离谱，score 却给 **0.9442**。
5. **汉字下标是 MinerU 的系统性硬伤**，不是偶发：全册 410 条公式条目里 **0 条含汉字**，
   而纸面确实印着 保/总/出/内/外/电/热（页图已证 6 处）。
