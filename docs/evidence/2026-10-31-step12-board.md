## 1. 第一项：内容齐全性（红线，全量不抽样）

判据（三选一都是结构性丢失，必红）：

1. 快照里每个块都必须在 DOM 里有对应 `data-bi` 节点；
2. 文本块的汉字数必须等于**渲染后应显示的汉字数**；
3. 图片块必须真的渲染出 `<img>`。

第 2 条的期望值不另立第三套口径，用渲染层既有的两处：
`mergePlan`（同页块级重复 → 丢掉并并集合并）与 `renderedTextOf`（`prettifyLatex` 后剥标签，
其中「即时重复前缀折叠一份」是原卷只有一份、上游读了两遍）。

| 指标 | 结果 |
|---|---|
| 页数 | 14 / 14 全部覆盖 |
| 快照块数 | 888 |
| DOM 渲染块数 | **888**（缺块 0） |
| 图片块 | 74，全部渲染出 `<img>`（缺图 0） |
| 汉字总数 | **9849**，逐块精确相等（不符块 0） |
| 零尺寸块 | 0 |
| 异常页 | **0** |

> 过程中出现过的两类「假红」，记下来免得下次重犯：
> ① 图片块的快照文本是占位符 `[图片]`（2 个汉字），按文本比会误判「空块」；
> ② LaTeX 被 prettify 成排版符号（`\frac`→竖排、`^{2}`→上标），按字母数字比会整页偏短。

## 4. 残留与判断

- **托盘 97px vs 目标 ≤96px**：超 1px。来源是「标题行 44 + 通道行 44 + 边框/内距」，
  属四舍五入级偏差，未改（改它要动 CSS 高度链，收益不足）。记在此，后续真机验收时一并看手感。
- **本审板不覆盖**：真机 iPad Safari（Step 13）、其它卷（本次只跑 1 卷 14 页）、
  `-OXR` / `-MinerU` 变体卷。
- 脚本口径的一个已知依赖：期望值取自渲染层同一模块（`mergePlan` / `renderedTextOf`）。
  这在此处是**正确的**（验证的是"渲染有没有丢东西"，不是验证去重/折叠规则本身，
  那两条各有单测）；若将来要审计这两条规则本身，必须换独立实现。
