## 六轮（用户截图反馈驱动的渲染审计升级，2026-10-08）

用户指出：① 对比模式选项粘连（`A.0.20B.0.30`，AB 靠太近）；② 第 4 页第 1 题公式 A 选项异常
（`A.Fsin^(:)θ`）；③ 「还有很多」，此前「截图自反馈」的迭代方式没迭代好。

**诊断（全量数据定位，非人眼翻页）**：

| 用户看到 | 数据来源 | 根因 |
|---------|---------|------|
| `A.0.20B.0.30` | `blocks[69]` ← `raw[21]` `A.0.20B.0.30C.0.35D.0.45` | **MinerU 丢列间距**（数据层本就无空格），展示层忠实显示 |
| `A.Fsin^(:)θ` | `blocks[10]` ← `raw[5]` `F \mathrm { s i n } ^ { \mathrm { : } } \theta` | **MinerU OCR 把 Fsinθ 误读**：`\sin`→`\mathrm{s i n}`，且凭空多出上标冒号 |

**方法论升级（回应用户「迭代没迭代好」）**：此前验收判据是「语法零残留」（输出无 `\` / `{}`），
但 `\varepsilon` 会被渲染成裸名字 "varepsilon"、`^{:}` 会被渲染成 "(:)" —— **语法干净、语义是错的**，
判据漏掉了整整一类缺陷，所以「全量清点 0 残留」之后用户仍一眼看到问题。
新增 `scripts/audit-render.mjs` 把判据升到**语义级**并接入 `npm run check`：

- 输出端：`^(标点)` / `_(标点)`、残留 `\` 与 `{}`、行尾裸上下标；
- 输入端：**未覆盖的 LaTeX 命令**（输出端查不到——未知命令已被丢弃、不留痕迹，只能在输入端查）；
- 选项粘连。

**首轮审计暴露的真实缺陷（五类，远超用户报出的两个）**：

1. 上标噪声 `^(:)`（9 处）；
2. 上标撇号 `^(′)` 应直出 `′`（如 `F₁′>F₁`）；
3. **`\thetaB` 被整体当未知命令丢弃 → 选项标记 B 消失**（内容丢失）；
4. 命令表缺映射：`\varepsilon`→"varepsilon"、`\vdots`→"vdots"，以及 `\varrho` / `\oplus` / `\varGamma`；
5. **裸公式判据太窄**：不含 `$` 但含 LaTeX 的文本（`F _ { 1 } = F _ { 2 }`）原样输出 → 阶段 1 源码残留 12+ 处。

**修复（`stages/latex-display.js`）**：

| 项 | 实现 |
|----|------|
| 上标语义化 | 内容为数学符号（′ ∘ ∗）直出；为纯标点（: . , ;）判 OCR 噪声丢弃；表达式才保留 `^()` |
| 命令表补全 | `varepsilon`/`varrho`/`varsigma`/`varkappa` 与大写 `var*` 变体、`vdots`/`ddots`/`cdots`/`colon`/`therefore`/`partial`/`nabla`/`sum`/`int`/`oplus` 等 |
| 最长已知前缀回退 | `\thetaB` 按 `\theta` + `B` 处理，杜绝「未知命令丢弃」把真实字符一起吞掉 |
| 未知命令不裸奔 | 丢弃命令名、保留参数内容；`\color{red}` 这类连参数一并丢弃 |
| 裸公式判据放宽 | 由枚举命令名的窄表 → 含任意 `\命令`，或「字母数字 + 上下标」 |
| 选项粘连分隔 | 同一文本出现 ≥2 个选项标记时补空格（单个标记多为正文引用，不动它） |
| `~` 还原空格 | LaTeX 不换行空格 → 普通空格（`10~kg` → `10 kg`） |

**验收**：`npm run check` = typecheck + **86/86 测试**（新增 9 例，用例全部取自真实样张）
+ **渲染审计 8 项全归零**。15 页对比截图重拍（`pages/compare-p0..14.png`）：
第 4 页右侧显示 `A.Fsinθ B. Fsin θcos θ`、第 2 页显示 `A.0.20 B.0.30 / C.0.35 D.0.45`，与预期一致。

### `.blk { overflow: visible }` 的去留结论

**保留 `visible`**。理由：
1. G1 明令「裁切文字 = 静默丢内容」，改成 `hidden` 会把本轮观察到的溢出**变成看不见的静默截断**，方向更错；
2. 本轮审板观察到的溢出（②(a)(b)、阶段 1）**不是 `overflow: visible` 造成的**，而是字号推算/适配逻辑
   （`fitFontSize` → `fontForBlock`、canvasW 口径混用、竖排块 bboxH 语义）造成的；`visible` 只是让问题**可见**，
   正是自反馈环需要的。
3. 因此：**保留 `visible`，溢出问题交回裁定**（见下节）。

### 8.3 保真度是否被 `clampByWidth` 削掉——**抽样实测（首次做）**

**方法**：`clampByWidth` 对 **441/964 = 45.75%** 的行级块生效（本轮复算确认）。
沿用 `data/out/ink-groundtruth.md` 的二值化方法（原卷页图 → bbox 外扩 6px → 灰度<128 二值化 → 墨迹包围盒），
量出每块**原卷墨迹隐含字号** `S_ink = 墨迹宽 / 全角字数`（F2 定义）；渲染字号取真实模块
`fontForBlock`/`clampByWidth`（与浏览器同一代码路径，对比栏口径 PANE_W=460）。
`ratio = 渲染字号(pt) / 原卷墨迹隐含字号(pt)`。
**独立证据**：重跑墨迹探针 `_t6-ink-fresh.json` 与既有 `_probe-ink-out.json` **逐字节一致**（输入未变，复用有效）。
输出：`data/out/_t6-fidelity.json`、`_t6-emraw.json`、`_t6-fonts-summary.json`。

**结果一（按 F2 有效估计量的子群）**：

| 子群 | n | p10 | **p50** | p90 | min | <0.95 |
|------|---|-----|---------|-----|-----|-------|
| 纯 CJK（`emWidthOf==全角字数`，N≥8）全部 | 124 | 0.897 | **1.0011** | 1.012 | 0.778 | 31 |
| 纯 CJK **被夹**块 | 45 | 1.004 | **1.0096** | 1.019 | **1.001** | **0** |
| 纯 CJK 未夹块（对照） | 79 | 0.879 | 0.9578 | 1.005 | 0.778 | 31 |

→ **对纯 CJK 正文行，`clampByWidth` 没有削保真**：被夹块 ratio 中位 **1.0096**、**无一 <0.95**（实际略 >1，
因夹后文字恰填 bbox，而 bbox 略宽于墨迹）。**「夹子削掉纯 CJK 保真」的担忧不成立。**

**结果二（含公式/ASCII 的块）——发现真实缺陷**：
把所有文本块按 `ratio` 汇总，中位仅 **0.856**（<0.95）。追因后**不是**「夹子把所有块都削了」，
而是 **`clampByWidth` 把 `emWidthOf` 喂给了「原始 LaTeX 文本」而非「渲染后文本」**：

- `emWidthOf(raw) > 1.2 × emWidthOf(渲染文本)` 的块 **158 个（16.4%）**；
- 被 `clampByWidth` **缩小 >1.3×** 的块 **142 个**，其中 `emRaw > 1.2×emRen` 的占绝大多数；
- 典型（`data/out/_t6-emraw.json`）：

| 页 | raw 文本 | 渲染文本 | emRaw/emRen | 基准字号→夹后 | 缩小 |
|----|---------|---------|-------------|--------------|------|
| p11 blocks[24] | `{ \frac { \sqrt { 3 } } { 3 } } m g` | `√33mg` | 12.25 / 3.0 = **4.08×** | 8.74px → **1.76px** | **4.96×** |
| p5 blocks[6] | `{ \frac { 5 } { 8 } } G` | `58G` | 7.85 / 1.5 = **5.23×** | 8.74px → **1.87px** | **4.68×** |
| p6 blocks[10] | `A.$\frac{m_a}{m_b}=\frac{\sin\alpha}{\sin\beta}$…` | `A.mamb=sinβsinα…` | 56.6 / 17.2 = 3.29× | 8.74px → 2.52px | 3.47× |

- **DOM 实测（全 15 页，`probe-fonts.html`）**：1015 个文本块中 **131 个（12.91%）字号 < 0.8× 基准**，
  **62 个 < 0.6× 基准**；这些块的**文字墨迹只填满 bbox 宽的 0.21–0.75**（若夹子正确应 ≈1.0），
  101/131 含数学符号或紧凑字母数字（即公式选项行）。最极端 `p11「√33mg」= 1.76px = 基准的 0.20×`。

**结论（直说，不替它辩解）**：
`clampByWidth` 的**意图**（行高模型在个别行过冲时压住横向溢出）对纯 CJK 是对的；
但它的**实现**用 `emWidthOf(block.text)` 度量的是**原始 LaTeX 源码**的当量宽（如 `\frac{\sqrt3}{3}mg` 记 12.25em），
而实际渲染的是美化后的短文本（`√33mg`，3em）。两者相差 **3–5×** ⇒ 对**含公式的块**，夹子把字号压到
**基准的 0.20–0.75 倍**，公式选项行小到几乎不可读。这是 Task 5（`clampByWidth`）引入的**真实回归**，
且因审计「可判块」口径排除了 `\`/`$`/ASCII，**判定项看不见它**（`npm run check` 全绿）。
**本轮不修**（简报硬约束：不得改 `clampByWidth`），**如实报告、交回裁定**。
