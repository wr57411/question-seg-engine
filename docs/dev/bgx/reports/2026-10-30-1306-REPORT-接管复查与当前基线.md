## 4. 缺口清单

### G01 [P2 / 已确认缺陷] 6 册 `meta.json` 体检摘要过期，成品页头部与 `/api/docs` 显示错误题数

- **证据**：§3.2 对照表；`/api/docs` 返回 `"questions": 31`；成品页头部截图。
- **触发与影响**：任何人打开这 6 册成品页/读 API 即触发；`needsReview`、`missingNumberGroups` 也可能同步过期。
- **建议（三选一或组合）**：
  1. **先修数据**：对 6 册跑
     `npm run daily -- "data/out/<docId>" --id "<docId>" --meta-only`
     （离线、不动产物；`importedAt` 会更新为刷新时刻）。
  2. **加门**：在 `check` 或单测里比对 `meta.stats.questions` 与 `questions.json` 长度、
     `meta.stats.pages` 与 `stages.pages`，不一致即红（反向验证：故意改坏一册必须红）。
  3. **治根**：`stages:export` 完成后自动重算 meta（或让导出命令附带 `--meta-only`）。
- **规模**：小。**边界**：写 `data/out`（git 忽略），不涉及仓库与页面逻辑。
- **依赖**：无。
- **处置（2026-10-30）**：已按 1 + 2 落地 ——
  6 册跑 `daily --meta-only` 刷新（`source` / `importedAt` 逐册核对未变；为此把 `--meta-only` 改为
  沿用旧 `source`/`importedAt`，因 `inferSource` 会把 `oxr`/`prebuilt` 误判成 `mineru`）；
  新增 `tests/meta-consistency.test.ts`（26 册全量扫描 0 不一致；反向验证：改坏一册即红并报册名）。
  记录：`DECISIONS §92`。

### G05 [P2 / 已确认缺陷 → 本轮试修后回退] 展示层 `.d.ts` 遮蔽实现，"纳管"只覆盖实现侧

- **证据**：删掉 `stages/reconstruct.d.ts` + `stages/uncovered-layout.d.ts` 后，`npm run typecheck` 立刻
  **113 处**错误（`reconstruct.js` 72 / `uncovered-layout.js` 41 + 1 处测试夹具）；根因是主 tsconfig 带
  `noUncheckedIndexedAccess: true` 而 `tsconfig.viewer.json` 刻意关掉它 —— 同一份代码被两套口径检查。
- **实际后果**：`final/`、`stages/` 引用的类型来自 `.d.ts`（多为 `any`），实现自带的 JSDoc 类型**不跨文件生效**；
  `dts-drift` 门只锁名字集合，**形状说谎不报**（`§31` 警告过的洞仍在）。本轮 `tag-panel.js` 纳管时
  就得手工 `/** @type {HTMLElement} */ (el(...))` 收窄，否则 `querySelectorAll` 回调退回隐式 any。
- **处置**：已回退删除（`.d.ts` 原样保留），并把删除前置条件与过渡规矩写进 `DECISIONS §94` +
  `HANDOFF §6-29`（先加唯一 bbox 读取口收口 113 处裸下标 → `typecheck` 0 错 → 再删 + 从 PAIRS 移除）。
- **规模**：中（收口本身机械，但要逐处判断"缺元素时该怎样"，且属显示层 ⇒ 需截图回归）。
- **边界**：不改主 tsconfig 的严格度（不许为通过而降门禁）。
