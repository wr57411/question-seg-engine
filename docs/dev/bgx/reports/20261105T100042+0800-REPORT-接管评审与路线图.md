## 3. 缺口（稳定 ID，证据 / 后果 / 建议 / 反例）

> 优先级按 bgx：P0 = 核心功能阻断或严重数据风险；P1 = 有证据的功能/边界缺陷或显著风险；P2 = 维护演进。

### G01 [P0 / 已确认缺陷] 金标准把「算 P/R 的独立题目清单」与「全文转写」捆进同一个 `complete` 开关

- **证据**：`scripts/score.ts:237-249` 的匹配按 `(page, number)` 建 `matchedPairs`；`:253` recall 分母是 `gold.questions.length`；`:254` precision **仅** `gold.complete` 时算。`gold/README.md:30` 规定「`complete:true` = 整本都标了」；`:32` 要求「回原卷页图转写」；BACKLOG B-08 把「整本完整金标」定为主路线。
- **后果（第一性原理）**：recall 只需要一份**独立于系统的完整题目清单**（页 + 题号 + 边界）；全文 `stem/options/answer` 是为「严格文本 / 选项完整 / 答案配对」这些**二级指标**服务的。现在两者共用一个开关 ⇒ 最便宜、最关键的 P/R 被「含公式全文逐题转写」拖住。项目自己 `HANDOFF §0.4:216-219`（P-1 回放：138 条修正里 **91% 不改题数**）已经证明题数尺子与内容尺子是**两个维度**，却在金标侧又把它们合成一个产物。
- **建议**：把金标拆成两级——**G1 结构金标**（独立题目清单，页/题号/起止边界，用于 recall/precision/切题边界）与 **G2 内容金标**（全文，用于文本保真；先只做公式密集的 1–2 本）。`score.ts` 增加按「结构金标」计算 P/R 的路径，`complete` 不再是唯一闸门。
- **反例 / 什么情况下这条不成立**：若项目要的「准确率」从一开始就定义为**整题文本级**（题干/选项/公式一字不差），而非切题级，则全文转写是必需的，G01 只是成本问题不是定义错误。→ 这一点**需要用户拍板**（见候选 PLAN 的 Q1）。
- **边界**：改评分器属业务代码；改 `gold/` 产物属数据；两者均未授权。

### G02 [P0 / 已确认缺陷] B-08 的立项前提已被 §108 自己收窄，台账没回头修订

- **后果**：一条已被自己证伪一半的依据，仍在驱动最贵的主线。要么重新论证「必须整本人工」，要么降档为「抽样 + 分流」。

### G04 [P1 / 已确认边界缺陷] recall 的分母是「金标题数」，`complete` 是无校验的自声明

- **证据**：`scripts/score.ts:253`；`gold/README.md:30,63`「整本标完后把 `complete` 改成 `true`」——代码里没有校验「金标题数 == 原卷题数」。工作表 `gold/worksheets/…电路-full.md:5-6` 要求「只用原卷页图转写，系统草稿只作定位参考」，但 :28「已有金标（沿用；仍建议抽看页图）」把独立核对降成**建议**；:13-26 的「系统草稿」与待判题是同一批候选。
- **后果**：违反 HANDOFF §5 红线 7（:792-793「判据的分母必须来自被检验对象之外的独立来源」）。人若从草稿定位，就看不到「机器根本没起草出来的题」——而 BACKLOG B-01 证明漏题确实存在。
- **建议**：人先在页图上**独立圈定本册共几题、每题边界与题号**，与草稿物理隔离；草稿只作事后比对；用 Word / `§102` 锚点给独立的题数上界兜住分母。
- **反例 / 不成立条件**：若标注流程实际是先数题号再看草稿（工作表 :5 的写法），则同源风险可控；当前文档没有把这一步写成**强制**。
