## 3. 主线现状：金标准（B01）到底是什么

**目的（一句话）**：给"切题切得对不对"找一把**不归系统自己吹**的尺子。
没有它，题数、`needs_review`、覆盖率都只是**系统自己的输出**，会把"题数变多"当成"变准"。
项目红线要求：**判据与实现不同源**，覆盖率的分母必须来自系统之外（原卷页图 / 人工转写）。

**实现（四件，都在库里）**：

| 件 | 位置 | 作用 |
|---|---|---|
| 名录 | `gold/registry.json` | 13 本在册：类别 A 原书扫描 / B 手机截图 / C 答案册，页数、题数、原卷 PDF 路径、金标文件路径、状态 |
| 金标本体 | `gold/<docId>.json` / `.pilot.json` | 每题 `{page, number, stem, options…}`，**必须回原卷页图转写**；关键开关 `complete`：`false`=部分金标，`true`=整本金标 |
| 标注工作表 | `gold/worksheets/<docId>.md`（`npm run gold:worksheet -- --all` 生成） | 每本抽 5 题（首/25%/50%/75%/末），贴页图路径 + **系统草稿（仅参考，不许复制）** + 空白金标模板；**脚本只生成表，不生成金标** |
| 评分器 | `scripts/score.ts`（`npm run score` / `score:all` / `check:accuracy`） | 金标 vs 系统输出逐题匹配；`complete:false` 时**只算 recall，precision 记 null**（防止拿系统自己的题数当分母）；自动通过要求 `complete && recall≥0.99 && precision≥0.99 && 待复核≤阈值` |

**实测家底（2026-10-30 22:0x）**：13 本合计 **1,086 题**，人工转写 **39 题 = 3.6%**，`complete:true` **0 本**。
最好的两本：电路 11/33（33.3%）、运动和力 7/24（29.2%）；三本"seed-verified"其实各只有 **1 题**。
→ 所以现在**任何整本准确率都说不出口**，`check:accuracy` 的结论就是"无法判定"。

**⚠️ 顺手记一处小漂移**：`registry.json` 里写的题数（如电路 33）是 10-28/29 的数，当前产物是 30 题；
下一位做 B01 时按 `data/out/<docId>/questions.json` 为准，别信 registry 的题数。

**建议的第一步（要用户点头）**：挑 **1 本**做完整金标（候选：`物理_教材基础练 电路`，30 题、已标 11、类 A），
把 `complete` 翻成 `true` ⇒ 让 `check:accuracy` **第一次真正可判定**；
再按 spec 的"10% 双标 + κ≥0.9"扩到分层 30 本。**人工转写这步 Agent 替不了**，只能把流水线和工作表备齐。
