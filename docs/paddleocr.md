



### **核心区别一句话：PP-StructureV3 是“装配式流水线”，靠一堆专用小模型拼出精确版面；PaddleOCR-VL-1.6 是“专职文档的 0.9B 视觉语言模型”，靠生成直接输出语义化 Markdown，精度更高但更像黑盒。**

你打开的这个页面里，下拉框中的三条线其实是三种完全不同的技术哲学，并非三个互相替代的模型版本。PP-OCRv6 是“识字”的那一层，负责场景文字检测加识别，单个模型覆盖 50 种语言、分 tiny/small/medium 三档；PP-StructureV3 和 PaddleOCR-VL-1.6 才是“读懂整页文档”的两条路线，也是你真正需要做选择的地方 [PaddleOCR](http://www.paddleocr.ai/v3.7.0/version3.x/pipeline_usage/PaddleOCR-VL.html)。

### **根本差别在“怎么干活”**

PP-StructureV3 是一条由多个模块组成的流水线：先用版面区域检测模型把页面切成标题、段落、表格、公式、图片、印章、图表等 20 多类区域，再分别交给表格识别、公式识别、印章识别、图表理解等专用子模块处理，最后按阅读顺序拼回 Markdown 或 JSON。它的 7 个模块可以单独训练、单独替换、单独关掉，还提供 default、full、lightweight 多档配置 [GitCode](https://blog.gitcode.com/8828afbad88e3e9cfd7625169434b7a3.html)。

PaddleOCR-VL-1.6 名义上是“一个模型”，实际上是一条两阶段管线：先由版面分析模型（PP-DocLayout 系列）定位元素并判断阅读顺序，把每个元素裁成子图，再逐个送进 0.9B 的 VLM 生成识别结果。这个 VLM 由 NaViT 风格的动态分辨率视觉编码器加上 ERNIE-4.5-0.3B 语言模型组成，本质是“看图说话”，靠自回归逐 token 输出内容，并非用检测框加分类器去判断 [alphaXiv](https://www.alphaxiv.org/zh/abs/2510.14528)。

### **关键指标对比**

| 维度 | PP-StructureV3 | PaddleOCR-VL-1.6 |
|---|---|---|
| 技术路线 | 多模块 pipeline，检测式 + 专用识别器 | 版面分析 + 0.9B VLM 生成式识别 |
| 精度表现 | OmniDocBench 编辑距离中英分别为 0.145 / 0.206，Pipeline 类第一 | OmniDocBench v1.6 达 96.33%，Real5 真实畸变场景 93.19% |
| 输出内容 | Markdown、JSON，**附带表格单元格、文本块等细粒度坐标** | Markdown、JSON，以语义内容为主，坐标粒度粗 |
| 语言覆盖 | 需通过 lang 参数指定语言、切换对应 OCR 模型 | 单一模型覆盖 100 多种语言，混合语种无需切换 |
| 可控性 | 模块级可裁剪、可微调、可用自有数据重训 | 参数少，主要靠整模型替换、prompt 和配置档位 |

精度这一栏要注意：两个数字**不能直接横比**。编辑距离是越小越好，96.33% 是准确率，而且评测集版本也不同。可以确定的是，在纯解析质量这条赛道上，VL-1.6 目前是 SOTA 级别，官方称其综合性能超越 Gemini-3-Pro、GPT-5.2 等通用大模型 [北京市科委](https://kw.beijing.gov.cn/xwdt/kcyx/xwdtkjqy/202606/t20260608_4690396.html)；而 StructureV3 的优势是在 Pipeline 类方案（MinerU、Marker、Docling 那一档）里领先 [OpenDeepWiki](https://opendeep.wiki/PaddlePaddle/PaddleOCR/core-pipelines.pp-structurev3-document-parsing)。

### **真正决定选型的三个实际操作差异**

**第一是坐标。** 这是 StructureV3 唯一无法被替代的地方。它输出的不只是文字，还有“这段文字在页面上的哪个矩形里”“这个表格的第 3 行第 2 列在哪”。如果你要做版式还原、原文高亮定位、可视化标注、PDF 结构化抽取、把识别结果回填到原文档坐标系里，VL 给不了你这个粒度，必须用 StructureV3。

**第二是鲁棒性。** VL-1.6 这一代专门针对真实拍摄场景做了优化，在扫描件、纸张弯折、屏幕翻拍、光照不均、倾斜文档这五类日常畸变上，指标全面优于对比模型，这也是你在这个页面上看到的“随手拍的卷曲试卷”演示想表达的东西。同时它在古籍、生僻字、手写、印章上的提升很明显，官方说 1.6 相对 1.5 在印章识别、文本检测识别、图表识别三个子任务上都有进步，且模型结构与 1.5 完全一致、可零成本迁移 [PaddleOCR](https://www.paddleocr.ai/main/en/version3.x/algorithm/PaddleOCR-VL/PaddleOCR-VL-1.6.html)。StructureV3 的强项则偏“标准文档”：多栏阅读顺序恢复、跨页表格合并、有线无线表格结构识别这些工程化细节打磨得更细。

**第三是资源与吞吐。** VL-1.6 只有 0.9B 参数，单张消费级显卡就能跑起来，显存门槛不高；但因为是逐元素、逐 token 生成，单页延迟会随页面元素数量线性增长，页数多的时候吞吐不如 pipeline 稳定。StructureV3 单模块都很轻，轻量档跑得很快，但如果开启全功能（表格、公式、印章、图表全开），叠加起来的显存占用会明显偏高。社区实测里对两者谁更快的说法并不一致，取决于你开了哪些模块、用哪档配置，所以别只看别人的跑分，最好用你自己的文档实测一遍 [什么值得买](https://post.m.smzdm.com/p/adoe5mkz) [CSDN](https://blog.csdn.net/2601_95956861/article/details/161056278)。

### **一个必须提醒的问题**

PaddleOCR-VL 的精度依赖**完整管线**。很多人图省事，直接用 Transformers 加载那个 0.9B 的 VLM 单独跑一张图，结果发现输出一堆幻觉文本、精度远不如宣传。原因是跳过了第一阶段的版面分析，模型不知道自己在读什么区域、该按什么顺序读。官方文档明确写了这一点：完整流程必须由版面分析模型加 VLM 协同完成，单独调用 VLM 组件不等于运行 PaddleOCR-VL [GitCode](https://blog.gitcode.com/55b2c6c1946927aff6e570407a575a0b.html)。

### **落到具体场景怎么选**

如果你的目标是“把一堆 PDF 转成干净的 Markdown 然后喂给大模型做 RAG”，对坐标没兴趣，文档里表格公式多、语种杂、还有扫描件和手机拍的图，那就直接用 PaddleOCR-VL-1.6，这是它最舒服的赛道。如果你的目标是“从文档里精确提取某个字段并定位回原文”、要给用户做原图上的框选高亮、要做表格单元格级的数据库入库、或者你需要在特定行业数据上自己微调某个环节的模型，那 StructureV3 的模块化结构才是对的，它允许你把表格识别换成自己训练的版本，而 VL 这条线基本做不到这种拆解。如果只是批量识别图片里的文字、不需要理解版面，那两条文档解析线都属于浪费，用 PP-OCRv6 的 tiny 或 small 档就够了。

实际工程里这两条线也经常组合使用：用 StructureV3 做版面切分和坐标抽取，把难啃的区域（古籍、手写、复杂公式）单独丢给 VL-1.6 精修。它们共享同一个 `paddleocr` 包，切换产线只是换个类名的事。
