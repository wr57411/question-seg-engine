# 专题、类别、业务标签三套清单独立

挑题归类需要「专题」（一题可进多个）与「类别」（全局多选教学标签，如基础/培优/易错）。
我们决定**不复用现有标签库**：专题、类别、现有业务标签（好题/待改/已校对）是三套独立清单，
题目分别保存 `topicIds`、`categoryIds`、`tagIds`。原因是业务标签描述的是录入/校对流程，
类别描述的是教学编排；混在一个库里会让筛选、统计、管理语义互相污染。

## 备选方案

- 复用现有标签库，加 `kind` 字段区分专题/类别：迁移最少，但管理界面仍混在一起，
  长期容易把「已校对」当成教学类别。
- 用命名约定（`专题:xxx` / `类别:xxx`）区分：零结构改动，但改名、多选、统计都脆弱。

## 后果

- 需要一次迁移：历史 `专题名#层级` 形式的标签拆成「专题 + 类别」两条记录。
- 展示层需要两套管理入口与两套归属数据；专题页的类别筛选按独立清单走。
- 现有业务标签面板保持不变，不与挑题托盘混用。
