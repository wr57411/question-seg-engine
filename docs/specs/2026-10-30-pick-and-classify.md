# SPEC — iPad 挑题与归类（专题 / 类别）

- 日期：2026-10-30
- 状态：已对齐，待拆分实施
- 关系：在 `2026-10-30-topic-knowledge-base-spec.md`（S01 专题展示）基础上，把「专题/层级」字符串模型
  升级为「专题 / 类别 / 业务标签」三套独立清单，并补上成品页的挑题交互
- 术语：见 `CONTEXT.md`；三套清单独立的理由见 `docs/adr/0001-topic-category-tag-separation.md`

## 1. 问题陈述

现有专题 MVP 只有「展示页 + 单题标签面板」：老师要在成品页点题号牌、打开面板、在扁平标签库里
反复找标签，逐题归类很慢；且 `专题名#基础` 把专题与教学类别挤在一个字符串里，无法表达
「一题进多个专题」「一题挂多个类别」「类别是全局教学清单」这些真实需求。

需要的是：在**不改动原版纸面布局**的前提下，点一道题就能当场把它归入若干专题与若干类别，
连续挑题时不给保存按钮、不打断节奏，并能临时新建专题/类别、改名、删除。

## 2. 方案概述

在成品页（`/final/`）增加**挑题模式**：

- 顶部一个「挑题」开关；关 = 原阅读模式，开 = 挑题模式。
- 挑题模式下，点一道题的任意内容块（题号/题干/选项/图）即选中该题；滑动不算点击。
- 底部常驻**归类托盘**：当前题 + 专题行 + 类别行 + 搜索 + 「同上题」+「管理」。
- 点专题/类别 chip **立即写入**（无保存按钮），再点已高亮的 chip 即摘掉；每次写入有撤销。
- 新专题/类别在托盘内联新建，永久进全局清单并立即打给当前题；重名复用已有项。
- 纸面题号牌加小角标 `N·M`（N 个专题 / M 个类别）；阅读模式下淡一档显示。
- 现有业务标签（好题/待改/已校对）继续留在题目详情面板，不进入挑题托盘。

专题页改为消费新的「专题 + 类别」数据合同，类别筛选为单选。

## 3. 用户故事（每条可独立验证）

### 3.1 进入与退出

- **U01** 成品页顶部有一个「挑题」开关；默认关闭。关闭时行为与现在完全一致（点题号牌打开详情/标签面板）。
- **U02** 打开挑题开关后，纸面布局、页高、字号、留白宽度与关闭时逐字节一致；只增加选中高亮与托盘，
  不重排、不压缩纸面。
- **U03** 挑题模式下滚动整册不会误选题目；从按下到抬起移动超过阈值（建议 10 CSS px）即视为滚动。
- **U04** 关闭挑题开关后，托盘收起，选中高亮清除，回到原阅读模式；已写入的归类不丢。

### 3.2 点题与纸面反馈

- **U05** 挑题模式下，点一道题的任意内容块（题号、题干行、选项、图片）即选中该题，托盘显示该题。
- **U06** 点两题之间的空白区或页边距不选任何题（不猜）；点在某题块外但距块 ≤6pt 时按该题处理。
- **U07** 当前选中的题在纸面上有**不改变几何**的高亮（块外描边/底色，不动 bbox、不改页高）。
- **U08** 题号牌显示归属角标 `N·M`：N = 该题所属专题数，M = 所属类别数；0 项不显示。
  挑题模式下角标清晰；阅读模式下同位置但透明度更低（建议 0.55）。
- **U09** 阅读模式点题号牌仍打开详情面板；详情里新增只读「教学归类」区（专题 chips + 类别 chips）
  与「去挑题修改」按钮，按钮进入挑题模式并选中该题。

### 3.3 托盘归类

- **U10** 托盘固定在底部，标题只显示 `p{页} · 第{题}题 · 已归 N 专题 / M 类别`（题干首行放 title，
  不再占托盘高度）；页面内容底部预留空间，点靠近底部的题时自动上滚，避免题被托盘遮挡。
- **U11** 托盘在**同一行内左右两个通道**：**专题** | **类别**。各自横向滚动，最近使用/最近归类的排最前；
  当前题已归的 chip 实心高亮；点一下即加入，再点即摘掉，立即写入并重绘角标；行尾「＋」固定可见。
  小屏（<560px）退化为上下两行；触控目标始终 ≥44px。默认高度约 96px（含 44px 标题行 + 44px 通道行）。
- **U12** 托盘顶部一个搜索框，同时过滤专题与类别；搜索不区分中英文标点；无结果时显示
  「新建『关键词』」的快捷入口。
  **落地细化**：搜索框与常驻组合条**共用标题行同一格**（开搜索即让位），托盘仍是两行、高度不变；
  关键词忽略首尾空格与英文大小写，两行各自显示命中数；点搜索结果即按普通 chip 语义归类（可撤销）；
  「清除」恢复完整列表且最近顺序不变；搜不到时给「新建专题『词』」「新建类别『词』」两个入口，
  建好即打给当前题并自动收起搜索；搜索本身只读，不产生任何写入。
- **U13** 点 chip 后无保存按钮；底部出现 `已放入：平抛运动 · 基础`（或 `已移出：…`）提示，
  5 秒内可撤销；托盘保持展开，直接点下一题即切换。提示条浮在托盘**上方**，不压 chip。
- **U14** 一题可同时属于多个专题、挂多个类别；每一类 chip 独立切换，互不隐含。
- **U15** 写入失败（网络/磁盘/校验）时，UI 回到写前状态并显示明确错误；不允许假装成功。
  同一文档的写入串行化，避免快速连点造成后写覆盖先写。

### 3.4 新建与管理

- **U16** 专题行尾有「＋ 新建专题」，类别行尾有「＋ 新建类别」；点开是一个输入框，
  回车或「建好并打上」后：永久加入全局清单 + 立即打给当前题 + 新 chip 滚到可见并高亮。
- **U17** 新建时若同名（去首尾空格后完全一致）已存在：不创建重复项，直接选中已有项并打给当前题。
- **U18** 托盘有「管理专题/类别」入口：列出两项清单及各自被使用题数；支持改名（按 id 更新，
  已归类题不受影响）与删除。
- **U19** 删除前显示「会影响 N 题」，二次确认后级联摘除所有题上的该专题/类别；删除后角标、
  托盘、专题页统计同步更新。
- **U20** 新建、改名、删除都立刻落盘；失败时显示错误并恢复 UI，不静默。

### 3.5 同上题与撤销

- **U21** 托盘有「同上题」：把**本会话最近一次已归类题**的专题+类别整体复制到当前题（替换而非合并）；
  若当前题就是上次归类题或本会话尚无归类，则禁用。
- **U22** 撤销只回退最近一次动作（加/摘 chip、同上题、新建后归属）；分类清单本身的创建不因撤销而删除。
  新动作发生后旧撤销入口失效。

### 3.6 专题页与导出

- **U23** `topic:export` 以「专题清单 + 类别清单 + 每题归属」为输入，输出 v2 index：
  每个专题的题条目带 `categories: [{id, name}]`，不再有 `level`；一题属于多个专题时在各专题各出现一次。
- **U24** 专题页：专题选择不变；类别筛选为**单选**（全部 / 该专题里实际出现的类别，带计数）；
  一题挂多个类别时，在每个类别筛选项下都出现；题卡显示类别 chips。
- **U25** `audit:topic` 独立复核：专题/类别清单 id 与名称唯一、归属不引用不存在的项、无重复归属、
  index 与源一致、类别 counts 与 stats 一致；断链/重复/缺项 ⇒ 退出码 1。
- **U26** 导出状态、漂移/失效规则沿用 S01：`export-status.json`、`stale` 专题关联、
  弱 anchor 告警、整专题消失报错；迁移后的归属同样带 anchor。
- **U27** 现有 `专题名#层级` 的标签与种子必须能一次性迁移为「专题 + 类别 + 归属」；
  迁移脚本默认 dry-run，写盘前备份，重复执行幂等；迁移后业务标签库不再含专题字符串。

### 3.7 阅读模式与业务标签隔离

- **U28** 现有业务标签面板（好题/待改/已校对）行为、文件、写通道不变；
  挑题托盘不显示业务标签，业务标签面板不显示专题/类别编辑入口（只读展示除外）。
- **U29** 阅读模式下角标淡显；挑题模式与阅读模式共用同一份归属数据，不产生两套状态。
- **U30** iPad 820 宽度下顶栏保持**单行**（目标 ≤56px）：`成品 / 文档选择 / 跳转搜索 / N / 总数 / 挑题 / ⋯`；
  审计标记、OCR 候选样式、本册体检、分阶段/阅读版链接收进「⋯」菜单。顶栏不竖排、不把页码挤成竖列。
- **U31** 顶栏与托盘的所有可点元素 ≥44px（coarse pointer）；小屏（<560px）托盘退化为上下两行，顶栏允许换行。
- **U32** 常用组合：把当前题的专题集合+类别集合存成一条**用户命名**的组合；名字不能自动生成
  「组合一」，必须由用户输入，trim 后全局唯一。
- **U33** 组合**常驻可见**（不再藏在按钮后面）：托盘标题行内一屏固定露出 **3 个组合槽**，字号 12px、
  槽高 40px（coarse pointer 下 ≥44px）；第 4 个起横向滑动找到；点一条即**替换**当前题归属并立即写入、
  可撤销；当前题归属与组合完全一致时该槽高亮。
- **U34** 组合槽右侧「＋」保存当前题为组合：当前题无专题/类别时禁用；保存后新组合立即进条。
  浮层只用于输入名字（保存），不再承担列组合的职责。
- **U35** 组合里引用的专题/类别后来被删除：套用时跳过缺失项并明说（不静默套用半套）；全部缺失则拒绝套用。
- **U36** 常用组合可**拖动排序**：长按 380ms 进入拖动，松手时按当前 DOM 顺序写回 `combos.json`；
  刷新后顺序保持；拖动结束附带的那一次 click 不得触发套用。
- **U37** 组合条不额外增加托盘高度：托盘仍是「标题行 + 双通道行」两行、总高 ≤96px（iPad 820 宽）。
- **U38** 组合可**改名与删除**：托盘标题行「管理」入口打开面板，列出全部组合（名字 + 成员摘要 + 条数）；
  改名按 id 更新、成员集合一个都不动，改成别人的名字要拒绝并提示；删除走**两步确认**
  （第一次点变「确认删除」，6 秒内不点第二下自动退回），且**只删这套预设**——
  已经按它归好类的题的归属一个字都不改（归属在 bindings，与 combos 无关）。
  新建/改名/删除/排序共用一条串行写路径，写失败回滚到改前清单并显示错误。

## 4. 已定决策

- **D01 归属模型**：一题可进多个专题；类别是全局、多选、教学用途，不隶属于专题。
- **D02 三套清单独立**：专题清单、类别清单、现有业务标签库互不混用（ADR-0001）。
- **D03 入口**：挑题是成品页顶部的模式开关，不是独立页面；纸面仍复用唯一 `renderPaper`。
- **D04 归类动作**：点专题/类别 chip 即生效，无保存按钮；托盘常开，下一题直接点。
- **D05 点选区域**：整道题的内容块 + 6pt 容差；滑动不算点击；空白不猜。
- **D06 托盘查找**：专题/类别双通道并排、各自横滑、最近优先、可搜索；多的时候靠搜索，不做分页。
- **D07 新增**：内联「＋」新建，永久进全局清单并立即打给当前题；重名复用。
- **D08 管理**：首版支持改名、删除（显示影响题数、二次确认）；不做合并。
- **D09 加速**：「同上题」复制最近一次归类；撤销只回退最近一次动作。
- **D10 纸面反馈**：题号牌 `N·M` 角标；阅读模式淡显；不做题目块彩色描边、不改留白短码列。
- **D11 专题页筛选**：类别单选（全部 / 逐个类别）；一题多类别会在每个类别下出现。
- **D12 业务标签隔离**：现有标签库不参与挑题托盘；专题/类别也不进业务标签库。
- **D13 顶栏收口**：顶栏只保留高频入口（文档、跳转/搜索、页码、挑题、更多）；审计/OCR/体检/链接进「⋯」菜单，
  避免 iPad 宽度下折成三行。页码显示 `N / 总数`，不写「第…页」。
- **D14 常用组合**：组合是全局清单（`teach/combos.json`），存 topicIds/categoryIds；名字用户自定义且唯一；
  套用=替换当前题归属，复用撤销；不做自动命名。
- **D15 组合常驻 + 手动排序**：组合是高频动作，藏在按钮后等于没有（用户原话「还要点一下才能打开，这哪是
  方便呢」）。因此组合条直接放在托盘标题行，一屏 3 个、超出横滑、顺序由用户长按拖动决定并持久化；
  代价是托盘比无组合版高一行、单槽文字只能放名字（摘要挪到 title 提示）。

## 5. 数据合同（v2 草案，实施时可增字段不可少字段）

目录：`data/out/teach/`（与快照、tags 解耦，可整目录备份/回滚）

```jsonc
// topics.json
{ "version": 1, "updatedAt": "ISO", "topics": [{ "id": "tp-…", "name": "平抛运动", "createdAt": "ISO" }] }

// categories.json
{ "version": 1, "updatedAt": "ISO", "categories": [{ "id": "ct-…", "name": "基础", "createdAt": "ISO" }] }

// combos.json（常用组合，全局一份）
{
  "version": 1,
  "updatedAt": "ISO",
  "combos": [{ "id": "cb-…", "name": "曲线基础", "topicIds": ["tp-…"], "categoryIds": ["ct-…"] }]
}

// bindings/<doc>.json（每卷一份，避免并行写冲突）
{
  "version": 1,
  "updatedAt": "ISO",
  "bindings": [{
    "questionId": "<doc>:p<页0基>:q<序>",
    "topicIds": ["tp-…"],
    "categoryIds": ["ct-…"],
    "anchor": { "number": "1", "page": 4, "section": "", "firstText": "…" }
  }],
  "stale": []
}
```

- `topics` / `categories` 的 `id` 由服务端生成；`name` 去首尾空格后唯一（大小写按原样，重复即复用）。
- `bindings` 按 `questionId` 至多一条；`topicIds` / `categoryIds` 去重、按清单顺序渲染。
- `stale` 结构与 tags 的 stale 同义：题目在快照里对不上时原样保留并在页面说明；导出/审计按 S01 规则判红。
- 写通道：`POST /api/teach?scope=topics|categories|bindings&doc=<docId>`；服务端白名单 + 路径断言 +
  形状校验 + 原子替换；`bindings` 的 doc 必须在 `data/out/<doc>/stages.json` 白名单内。
- 专题页 index v2：
  ```jsonc
  { "version": 2, "generatedAt": "ISO",
    "topics": [{ "id": "tp-…", "slug": "…", "name": "平抛运动",
      "items": [{ "doc": "…", "number": "1", "page": 4, "questionId": "…",
        "stem": "…", "options": [], "images": [], "answerKey": "…", "answerText": "…",
        "answerDoc": "…", "answerImages": [], "status": "ok", "confidence": 1,
        "reviewFlags": [], "categories": [{ "id": "ct-…", "name": "基础" }] }] }],
    "stats": { "topics": 1, "items": 1, "needsReview": 0, "byCategory": { "ct-…": 1 } } }
  ```
- `export-status.json` 沿用 S01（加 `warnings`），审计要求 `ok:true` 且与 index 的 `generatedAt` 一致。

## 6. 接缝与测试决策

**接缝优先级：先纯逻辑，后 DOM。**

1. `final/teach-store.js`（新，纯函数，`@ts-check` + JSDoc，纳入 tsconfig）
   - 接缝：`normalizeTeach({topics,categories,bindings})`、`toggleTopic` / `toggleCategory`、
     `sameAsPrevious`、`renameTopic` / `deleteTopic` / `renameCategory` / `deleteCategory`、
     `affectedCount`、`assignmentFor`、`badgeCounts`。
   - 测试：多专题/多类别、幂等、重名复用、改名不改归属、删除级联计数、stale 不丢、
     `sameAsPrevious` 替换语义、撤销快照、写失败回滚（以纯状态函数模拟）。
2. `scripts/teach-write-guards.ts`（新，纯函数 + 少量 fs）
   - 接缝：scope/doc 白名单、路径越界、载荷形状、2MB 上限；`POST /api/teach` 只调用它。
   - 测试：与 `tests/tag-write-guards.test.ts` 同构；路径穿越、非法 scope、缺 doc、超限、重复 id。
3. `final/pick-hit.js`（新，纯函数）
   - 接缝：`pickQuestionAt(page, questions, {xPt,yPt}, tolerancePt)`；输入是页面单位坐标。
   - 测试：块内命中、6pt 容差内、空白不选、跨栏题、重叠块取最近、题号牌优先。
4. `stages/reconstruct.js` 的 `renderPaper`（改选项，不改纸面几何）
   - 新选项：`assignmentBadge: (q,p) => {topics:number,categories:number}|null`、
     `dimBadges: boolean`、`pickMode: boolean`；只在 wrap/号牌上加类与角标。
   - 测试：扩展 `tests/layout-invariant.test.ts`——开关挑题/有无角标，纸面几何逐字节相同、
     留白宽度不变、号牌数量与位置相同；角标只出现在 q-chip 内。
5. `final/final.js`（组合层）
   - 接缝：`openPickMode` / `closePickMode`、`selectQuestion(q,p)`、`commitTeach(mutation)`、
     `undoLast()`、`sameAsPrevious()`；只消费 `teach-store` 与快照。

## 7. 明确不做

- **不做多选批量归类**：本版固定「一次一道题」；批量留给后续（用户已明确）。
- **不做拖拽**（把题拖进专题/类别）。
- **不做专题/类别合并**；只做改名、删除。
- **不做 AI 自动推荐选题/分类**。
- **不碰纸面重排**：不改变 `renderPaper` 的坐标、字号、留白、页高；不新增第二套纸面实现。
- **不复用业务标签库**做专题/类别；不把专题/类别写进 `data/out/tags/`。
- **不做公网部署/鉴权**：写通道仍限局域网；公网前必须另立安全项。
- **不做语音/手写标注**（S04 探针之后再说）。

## 9. 风险与待核实

- **纸面命中**：文字块之间有空隙，6pt 容差是否足够需实测；空白处不猜可能让用户觉得「点不动」。
  若实测误选多，缩小容差；若点不中，改为按列合并块区间，但必须保持几何不变。
- **托盘遮挡**：iPad 竖屏 820×1100，托盘约 200px；需 `scroll-margin-bottom`/自动上滚。
- **键盘**：新建输入框在 iPad 上会被键盘顶起；需用 `visualViewport` 或 CSS 变量抬升托盘。
- **写入竞态**：快速连点同一题或多个 chip，必须串行写；失败回滚并提示。
- **清单膨胀**：专题/类别可能很多；最近优先 + 搜索是首版方案，后续再看收藏/分组。
- **迁移不可逆**：`migrate-teach.ts` 默认 dry-run；写盘前备份 `data/out/tags`、`data/out/topics`、
  `data/out/teach` 到 `data/archive/<date>-teach-migration/`；迁移后保留旧文件至少一轮。
- **真机验收**：截图是 headless Chrome；iPad Safari 的触控/键盘/滚动惯性必须人工过一遍。
