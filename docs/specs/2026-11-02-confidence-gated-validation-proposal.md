## 0. 项目背景（给不了解本仓库的评审者）

`question-seg-engine` 是扫描件试卷的**解析后处理层**：

```
扫描 PDF ──▶ MinerU 云 API（版面 JSON：块/行/坐标）
                  │
                  ▼  本项目 src/
        归一化 → 版面层（分栏/阅读顺序）→ 语言层（题号/选项/答案区模式）→ 状态机切题
                  │
                  ▼
        questions.json（题干/选项/答案/图片 齐全的结构化题目）+ 成品页（按原坐标重建的纸面）
```

技术栈 TypeScript ESM + `node:test`，零运行时依赖。质量门是 `npm run check`
（类型检查 + 498 测试 + 渲染审计 + 题号审计 + 交叉审计 + 锚点对账 + 题库配对）。

**三条与本案直接相关的红线**（违反即方案不成立）：

1. **不静默失败**：低置信必须留 `needs_review` 记录，不许悄悄放过。
2. **判据与实现不同源**：覆盖率/准确率的分母必须来自被检验对象**之外**。
3. **检测不改写**：统计工具不改数据；清洗须显式决策。

## 1. 现方案（整本金标准）为什么走不通

| 事实 | 数字 | 出处 |
|---|---|---|
| 登记在册需做金标的书 | 13 本 / **1,086 题** | `gold/registry.json` |

| Word（夸克扫描王真文字）能起草多少 | 《电路》31 题里 18 题文字可起草 | `docs/evidence/2026-11-02-金标-word起草试跑.md` |

⇒ 「人做不完 8,000 题」这个论据**不再成立**；仍然成立的论据是
「**每本都要**整本金标的稳态人工 ≈ 1–6 小时/日，不值得」——所以结论从「取消金标准」
改为「**金标准抽样化**」（§9.4）。任何「读图录入」同样会错，只是它的错没被度量。

## 3. 方案总览

```
一份扫描卷
   ├─▶ 源1 MinerU layout（几何 + 文本，公式=LaTeX）
   ├─▶ 源2 OXR（第二解析源）
   ├─▶ 源3 PaddleOCR-VL（整页，含 LaTeX；贵）
   └─▶ 源4 夸克 Word（真文字，公式=图片；便宜）
                    │
                    ▼
      结构判据层：题号连续性 / 选项齐全 / 回拼校验 / §99 交叉 / §102 锚点
                    │
                    ▼
      置信分 conf(q) = f(源间一致性, 结构判据, 选源代价, 公式/图片密度)
                    │
     ┌──────────────┼───────────────────┐
     ▼ conf ≥ 高阈值   ▼ 中间带              ▼ conf < 低阈值
  自动放过，进成品   截图判别器（非 LLM）    标 needs_review + 证据
                    裁图 + 候选文本 → 像/不像   （目标占比个位数%）
                              │
                              ▼
                    仍不确定 → needs_review
```

### 3.1 置信分（把已有的裁决逻辑收敛成一个可打分函数）

| 信号 | 来源 | 现状 |
|---|---|---|
| s1 源间文本一致性 | `normForScore` + `similarity`（§63/§73 已有） | 已有，散在选源逻辑里 |
| s2 结构判据通过 | N1–N8 编号审计、§99 X1/X2、§102 锚点差 | 已有，输出是「报警/不报警」，未打分 |
| s3 选源代价 | §73「两源互不相似 ⇒ 升级仲裁」 | 已有，是二值，未分级 |
| s4 公式/图片密度 | 题干 `$…$` 计数、`images[]` 数量 | 未使用；历史上含公式题更易错 |

⚠️ **conf 度量的是 agreement，不是 correctness**——这是本方案的命门，见 §4。

### 3.2 截图判别器（明确不用大模型）

任务形态是**判别**不是生成：输入「一张裁图 + 一句候选文本」，输出「像不像（0~1）」。

| 方案 | 单题成本 | 备注 |
|---|---|---|
| **双塔嵌入**（图塔/文塔，余弦相似度） | 一次向量调用 | 候选：局域网 WeMM-Embedding-2B（2048 维，图文互搜）/ EmbeddingGemma（768 维）。**2026-11-02 实测两者当前不可达（`/health` 连接失败），需先确认部署、以及图文是否同一向量空间** |
| 裁图级 OCR + 现有 `similarity()` | 一次小 OCR | `stages:ocr-fill` 已有；公式识别弱 |
| 整页 PaddleOCR-VL | 75–90 秒/页 | 太贵，只用于「整页对齐失败」的少数页 |
| 大 VLM 逐题看图 | ≈ 200 万 token / 6–10 小时每本 | **已否决（N-05）**，本方案不采用 |

**先做可证伪实验**（Phase 0）：拿现有 39 题当正样本、故意改错的题当负样本，
测双塔相似度能不能把两组分开（AUC / 两组中位数间距）。**分不开就整条 3.2 放弃**，
退回「纯 agreement + 结构判据」，不硬撑。

### 3.3 新的质量门（替换 `check:accuracy`）

```
① 自动通过率        ≥ X%      （机器自认「可放过」的题占比）
② 自动通过部分错误率 ≤ Y%      （靠 §4 的标定曲线给上界，不靠全量金标）
③ needs_review 占比 ≤ Z%      （人/后续工具只需处理这一小块）
```

## 4. 命门：agreement ≠ correctness，所以必须标定

实测已经证明「一致但错」存在：**双源都错 8%**（§70）。这类错误再多源一致性也看不见。
所以「conf ≥ 阈值就放过」这句话，必须有一条 **agreement → correctness 的标定曲线**支撑。

### 4.1 标定 ≠ 验收（本案的核心区分）

| | 验收（旧方案） | 标定（新方案） |
|---|---|---|
| 量级 | 随书目线性增长（1086 → 8000/日） | **一次性**，不随规模增长 |
| 谁做 | 人（不可持续） | 人只签一次，或完全机器 |
| 用途 | 判每本书的分数 | 画一条曲线，之后机器自判 |

### 4.2 两条标定路线（互补，建议都做）

| | A. 小样本签字 | B. 合成回环 |
|---|---|---|
| 做法 | 按 conf 分桶，每桶抽若干题，人只判「对 / 错 / 正确写法」 | 自己排版生成**已知正确**的题目 → 渲染成图 → 喂进整条管线 → 量还原率 |
| 人的量 | 一次性（见 4.3 对样本量的诚实估算） | **0** |
| 能标 | agreement↔correctness 的真实曲线，含「双源一起错」 | 管线丢字 / 丢结构 / 公式错位 / 阅读顺序错 |
| 标不了 | — | **原书被两台 OCR 一起看错**（无独立真值） |
| 代价 | 一次性人工 | 要写渲染器（HTML/PDF 模板 + 排版脚本） |

### 4.3 样本量的诚实估算（这条是本案最容易被质疑的地方，请重点评审）

要用 n 个样本「看到 0 个错误」来给错误率 p 的 95% 置信上界，近似 `p ≤ 3/n`（rule of three）：

```
n = 100  → 上界 3%      ← 只能证明「不是灾难」，证明不了 99.5%
n = 600  → 上界 0.5%    ← 对应 spec Q2 的 99.5% 目标
n = 300  /每桶 → 上界 1%
```

⇒ **「~100 题标定」不足以支撑 99.5% 的承诺**。可行的折中：

1. **分桶标定**：只在「高 conf 桶」抽样，桶内给保守上界；不同桶不同阈值。
2. **合成回环兜大头**（B 路线，0 人工、样本可以上万），把「管线丢字」这类错误压到可测。
3. **接受一个盲区**：「多源一致但都错」的题，只用月度抽书 + 用户反馈兜，不承诺 0.5%。
4. 或者**下调承诺**：从「99.5% 准确率」改成「自动通过率 ≥X%，且抽检错误率 ≤Y%（Y 由样本量支撑）」，把 Y 定在能证明的水平。

## 7. 风险与已知弱点（不藏）

1. **相关性错误**：MinerU / OXR / PaddleOCR / 夸克可能共享训练数据或同源模型，agreement 会系统性高估。
2. **公式是最难的一类**：Word 完全给不出，嵌入模型对 LaTeX 结构（上下标、分式、单位）可能不敏感 ⇒ P0 必须先证伪。
3. **合成回环分布不同**：自己排版的图比真扫描干净，还原率会偏乐观。
4. **阈值定高 ⇒ 错误静默进题库**，直接违反红线 1 ⇒ 必须保留 `needs_review` 与抽检，且门的反向验证要实测。
5. **种子太少且可能偏易**（39 题是试点挑的），曲线置信区间宽。
6. **局域网嵌入服务当前不可达**，双塔方案的前置条件还没验证（图文是否同一向量空间、是否支持公式图像）。
7. 本方案会让「准确率」这个词的含义改变：从「对金标准的 precision/recall」变成「标定曲线支撑的置信上界」——**对外沟通口径要同步改**，否则是换个说法自夸。

## 8. 请评审模型具体回答的问题

1. 在「面向真实交付的题库」场景下，取消整本金标准、改用 **agreement + 一次性标定**，是否可接受？还有没有第三种更便宜的真值来源（例如教材官方电子题库、出版社勘误、多用户行为一致性）？
2. §4.3 的样本量估算是否成立？若目标是「自动通过部分的错误率 ≤0.5%」，**分层抽样最少要多少题**？有没有比 rule-of-three 更省样本的统计设计（序贯检验 / 贝叶斯先验 / 缺陷注入放大）？
3. 截图判别器用双塔嵌入现实吗？对**物理公式**应该做图像级比对还是「OCR→LaTeX→AST 结构比对」？中间档（裁图级小 OCR + 文本相似度）是否已经够用，从而根本不需要嵌入模型？
4. 合成回环能否作为**主要**标定手段？要覆盖「多源一致但都错」需要怎样设计（例如故意构造易混字形、低对比、倾斜、水印遮挡）？如果覆盖不了，接受这个盲区吗？
5. 置信分 s1–s4 怎么组合才不会自证（红线：判据与实现不同源、分母须来自被检对象之外）？用规则打分、逻辑回归，还是直接保留固定比例的人工审计抽样？
6. 新门（自动通过率 / 抽检错误率 / needs_review 占比）能否替代 precision-recall 作为验收？X/Y/Z 建议定多少，理由？
7. 如果只能保留**一个**最便宜的机制来防止「静默错误进题库」，你会选本案里的哪一个？

## 9. 前提修订与评审回应（2026-11-02 晚）

评审原文已归档：[`docs/reviews/2026-11-02-外部评审-置信门控方案.md`](../reviews/2026-11-02-外部评审-置信门控方案.md)
（结论：作为「逐题替代人工」的精度方案不成立，作为「人工注意力分流器」有价值）。

### 9.1 用户下调了吞吐前提

> 「一天不要 100 本，我说夸张了，一天能完成一本就可以。」

`100 本/日` 这个从未被验证的假设，是**本方案与整份 spec 的地基之一**。改口后的算术：

```
1 本/日 ≈ 15 页 ≈ 80 题/日
  残留仲裁 10%（§74）  → 8 题/日      （旧口径 800 题/日）
  待校对 15.8%         → 12.6 题/日   （旧口径 1,264 题/日）
  复核预算 ≤1%         → 0.8 题/日
  存储                 → ~35MB/日、30 天 ~1.0GB
  MinerU 额度          → 15 页/日 = 1.5%，不再是约束
```

### 9.2 评审八条「致命问题」的逐条处置

| # | 评审意见 | 处置 | 理由 |
|---|---|---|---|
| 1 | conf 度量 agreement，与「共错」正交 | **接受** | 标定路线改成 §9.4 的组合，不再指望 agreement 自己说话 |
| 2 | 唯一独立源（Word）恰好丢公式 ⇒ 难类无独立源 | **部分接受** | 准确说法是「难类只有另一台 OCR（PaddleOCR-VL，与 MinerU 不同厂商），没有**非 OCR** 的独立源」。区别重要：要防的是共错，不是「没有第二意见」 |
| 3 | 「取消人工」是话术：800 题/日队列 | **因前提改变而失效** | 8 题/日 人十几分钟能清完。方案定位从「取消人工」正式改为「**把人工压到每天十几分钟，并承诺清完**」 |
| 4 | 样本量乐观 + 聚类效应；3/36 的 CI 太宽 | **接受** | 采纳「缺陷注入测检出率 d + 以书为单位的整群抽样 + 设计效应校正」；并承认 600 题零错误才撑得起 0.5% 上界 |
| 5 | 双塔嵌入不是验证器 | **接受，换路线** | 公式改走 **OCR→LaTeX→AST 结构比对**（能定位到上下标/分式节点），向量相似度降为「粗筛」，不当判据 |
| 6 | 合成回环只能当 CI 金丝雀 | **部分接受** | 它测不了「两模型共有的先验偏差」，对；但它能量化**管线自身失败面**（丢字/丢结构/阅读顺序/公式错位）——这是真实错误分布里占比不小的一片，且是唯一能 0 人工上万的。定位改为「标定的一半 + CI 金丝雀」 |
| 7 | 新三门仍违反红线 2（抽样框由 conf 定义 ⇒ 同源） | **接受，这是最狠的一刀** | 抽检必须用**独立抽样框**（对已交付题随机抽，不按 conf 分层），并把 s0 换成**非 OCR 的像素域信号** |
| 8 | 缺分层指标与严重度加权 | **接受** | 指标拆到 公式/图片/跨页/多栏 四层；错误分级：缺题 > 答案错 > 选项错 > 文本微差 |

### 9.3 评审的 5 条修正，采纳情况

### 9.4 修订后的方案定位（一句话）

```
旧：置信门控 → 替代金标准 → 不需要人        ← 评审说得对，不成立
新：抽样金标（1–2 本完整）定阈值 + 置信分流 + 像素域独立信号
    ⇒ 人每天只清 ~8 题队列；每月抽 1 本防漂移
```

**为什么还要抽样金标（改口后反而更该做）**：1 本/日 的规模下，
「做 1–2 本完整金标」= 机器起草 + 人判对错 ≈ **4–9 小时一次性**，
换来的是**第一次能真算出 precision/recall**，以及一条不是构造出来的标定曲线。
原方案「取消金标准」的动机（1086 题做不完）在改口后已经弱化，只剩
「**每本都要**金标的稳态人工 ≈ 1–6 小时/日 不划算」——所以是**抽样化**，不是取消。

### 9.8 P-1 已跑完：结论比评审说的更糟，但出路也清楚了

完整数据见 [`docs/evidence/2026-11-02-P1-corrections回放证伪.md`](../evidence/2026-11-02-P1-corrections回放证伪.md)。

```
138 条已核对真实缺陷（corrections，verified:true）逐条拿掉后：
   改变题数（结构性）        13 条 =  9%   ← 结构尺子唯一能看见的那一维
   不改变题数               125 条 = 91%   ← 其中 100 条「整行内容漏读」+ 21 条「字认错」
结构性 13 条里：有题号脚印 12、完全静默 1（运动和力 p10，少 2 题而题号序列毫无异常）
```

⇒ **不是「共错看不见」一个洞，是主信号选错了维度**：题号/结构只覆盖 9% 的已知缺陷面。

⇒ 修正后的架构（替换 §3 的主信号）：

```
主信号：每道题至少两个独立文本源的证据（MinerU / OXR / 整页 OCR / Word）
        conf = 文本证据一致度（汉字窗覆盖 + AST 比对），不是题号一致度
第二层：结构判据（§96 脚印 / N7 / §99 / §102）—— 覆盖 9%，仍然要留，因为它便宜
```

⇒ **成本可行性被今晚的吞吐改口翻转**（这是 P-1 真正的决策价值）：

```
整页 OCR 75–90 秒/页 ⇒ 1 本 15 页 ≈ 20 分钟/本   ← 1 本/日 可接受
旧口径 100 本/日 ⇒ 33 小时/日                    ← 当时不可能，才退而用结构尺子凑
```

⇒ 已知偏差（报告里写明，不许当结论用）：回放未注入 OCR 题号行（会高估「改变题数」）；
「有脚印」≠「闸门当时会响」（登记表模式）；138 条是**已发现**的缺陷，分布本身有偏，
**只能否证、不能定标**——定标仍需 §9.4 的抽样金标。
