## 1. 问题陈述

成品页现在是一台"只读的印书机"：逐页翻整册，能看到题号、能点开详情看配对答案，
但**没有任何地方能留下人工判断**。"这是好题""这题切坏了""留着组卷用"只能记在脑子里或外部文档。

标签是后续三件事的共同地基：筛题、组卷、质检闭环（"待改"= 人工版 needs_review）。
本期要的是一条**能被下游消费的人工标注轨道**，且存储形态下游拿得到。

### 硬约束（实测与出处，不是推测）

| # | 约束 | 出处 | 后果 |
|---|---|---|---|
| C1 | 纸面**没为标签留任何版面**：题号牌独占 22px 留白，号牌自身 `min-width:15px / font-size:10px` | `stages/reconstruct.js:23,287`、`stages/stages.css:459` | 加宽留白 → `innerW` 变小 → 整页字号与行位再缩，直接回退 `6c26e9d「题号牌只写数字 + 留白收窄 —— 页面不再被挤小」` |
| C2 | `.canvas{overflow:hidden}` 既定决策不改 | `DECISIONS §20.3`、`stages.css:143` | 画布内标签越界即被裁：**DOM 有、位置对、看不见**（号牌 2026-10-12 踩过） |
| C3 | `questions.json` / `stages.json` 每次 `npm run stages:export` **整体重生成** | `package.json` | 标签写进快照 = 必被冲掉。独立存储是物理必然，不是洁癖 |
| C4 | `view-server.ts` 是**只读**静态服务器（GET + 白名单，无 POST） | `scripts/view-server.ts:31-57` | 落盘需新开写通道，是本项目**第一条写路径**，须按安全口径设计 |
| **C5** | **手机视口下成品页正文只有 5.67px**（实测：390pt 视口 → `paperWidth()` 被 `Math.max(320,…)` 兜到 320 → `innerW=298` → `baseFontOfPage`=5.67px；760px 时同页为 14.03px） | `final/final.js:40-42`、`stages/font-metrics.js:361`，2026-10-15 用真卷 p1 计算 | **手机上用户根本读不清题干**，标签做得再大也救不了。这是标签功能的前置缺口 → **拍板 Q6** |
| **C6** | `npm run view` 只打印 `localhost` 地址 | `scripts/view-server.ts:61-65` | 手机/平板打不开页面。触屏一切验收的前提是先能从局域网访问 → **U27** |

**平板（iPad 竖屏 820pt → 纸面 710px、正文 ≈13px）现状可用；手机（390–430pt）现状不可读。**
本规格的交互按"触屏为主、桌面为辅"设计，验收以 **iPad 竖屏**为基准机型，手机端结论单列 §2.3。

## 2. 用户与场景

主用户不变：出题老师 / 教研员。**主设备：平板（躺沙发/教室里翻）、手机（碎片时间）；桌面退为次要场景。**

- **T1 边翻边标（最高频）**：整册滚动翻，遇到要记的题就地打标，不停下、不切模式、不打字。
- **T2 回头看清**：标完 20 题扫一眼"我标了哪些"——标签常驻可见。
- **T3 改主意**：标错了就地摘掉/换标签，不需要"编辑模式"。
- **T4 建词表**：第一遍建自己的标签库，之后复用。
- **T5 隔天回来**：关浏览器再开，标签还在、位置还对。
- **T6 单手操作**：平板竖屏单手持握，拇指够到屏幕下半部——**这决定了操作面板必须在下方，不能在题目旁边**。

### 2.3 触屏带来的三条设计改写（相对 v1）

1. **没有 hover**：一切"悬停才出现"的显隐在触屏上不成立，入口必须常驻或靠一次可发现的手势。
2. **没有右键**：上下文菜单只剩长按，而长按在 iOS 上会与文本选择/放大镜（约 500ms）抢手势。
3. **12px 的目标不能当交互控件**：留白里堆叠的短码块行距 12px，把热区扩到 44px 就会与相邻题的标签列重叠 → 必然误触。
   ⇒ v2 的核心改法：**常驻层只读、交互全部收进底部面板**（§3）。

## 3. 方案概述（三层）

```
┌─ 常驻层（只读，进版面）  号牌下方 22px 竖列里的短码标签 ≤3 个 + 折叠计数
│                          pointer-events:none，不承担点击 → 因此不需要 44px 热区，也不碰版式
├─ 手势层（画布外）        点题号牌 = 打开底部操作面板；长按号牌 = 快速菜单（摘除本题全部/进面板）
│                          号牌是纸面上唯一的 tap 目标，四周都是留白，扩热区到 44×44 无碰撞
└─ 面板层（fixed，画布外）  复用现有详情抽屉改造成下半屏面板：标签区置顶 + 详情在下
                           所有加/改/删标签的动作都在这里完成，行高 ≥44px、字号与缩放解耦
```

**为什么交互不能贴在题目旁边做（一句话）**：纸面会随双指缩放改变视觉尺寸，而 `fixed` 面板不随页面缩放——
把可点的东西放在面板里，"点得准"就跟用户把页面放大到多少无关；放在留白里，就永远受 22px 与 12px 行距的死约束（C1）。

**深模块取向**：三个接缝，底层随便换，测试只打这三个。

| 接缝 | 稳定接口 | 复用了什么 |
|---|---|---|
| A 渲染 | `renderPaper(p, { tagLayer })`，与现有 `diagnostics`/`candidateStyle` 同一可选 opt 模式 | **纸面重建仍只此一处实现**（红线）：`stages/reconstruct.js`。成品页与 stages「成品/对比」自动同获标签层 |
| B 数据 | `final/tag-store.js`：`load(docId) / save(docId, bindings) / library()` | 与 `final.js` 现有 `loadBank()` 同构（拉 JSON、建 Map、拿不到就 null 不报错）；写经新增 `POST /api/tags` |
| C 不变量 | `gate-layout-invariant`：标签层开/关两跑，逐块比对 `.blk`+`.q-chip` 的 `getBoundingClientRect()` 与 `.txt` 的 `font-size` **必须全等** | 复用 `scripts/browser-gate.mjs` 的 DOM 探测通道与 `npm run view:cap` 截图审板 |

接缝 C 把"版式不变"从口头承诺变成一条机器可判的门。

## 4. 功能需求（用户故事，每条可独立验收）

### 可见性

- **U1** 打开成品页，已打标签的题，其标签**默认可见**，无需开关、无需进模式。
  验收：任一带标签题，`.qtag` 可见且未被裁切（**以截图为准**，DOM 存在不算过）。
- **U2** 标签显示在**题号牌同侧留白内**、紧跟号牌下方竖排。双栏页右栏题随号牌挂右侧留白（沿用 `isRightCol()`，不另起一套）。
- **U3** 显示**短码**（1–2 字）+ 底色，全称在 `title` 与面板里。最多 3 个，第 4 个起折为 `+N` 计数块，点开面板看全部。
  验收：4 标签题显示 3 短码 + `+1`，面板里 4 个全在——**折叠只影响显示，不影响数据**。
- **U4** **常驻短码块为只读**（`pointer-events:none`）：不可点、不可长按。
  打标/摘除的入口永远是题号牌（它已经是可点的，现有行为是打开详情抽屉，本期在抽屉里加标签区）。
  理由：见 §2.3-3；副带好处——不会拦截滚动、不会触发 iOS 文本选择。
- **U5** 标签视觉尺寸**不得大于题号牌**（`font-size:9px, line-height:12px, 宽 ≤22px`）。
  验收：面板关闭状态下，标签层开关前后接缝 C 的门必须全绿。
- **U6** 留白竖列总高 = 号牌 + min(标签,3)。**同侧相邻题的标签列垂直重叠时**（密页，如答案册 86 块/页）后到者折为单个计数块；
  一个都放不下时降级为仅面板可见 + 号牌上 `n` 角标——**降级必须在页面上可见**，绝不静默丢标签（红线 G1）。
  验收：答案册逐页截图，无标签压正文；降级页数有计数报告。

### 打标（2 次点击，零输入）

- **U7** 点题号牌 → 底部面板打开，**标签区在最上方**，列出标签库全部标签为 ≥44px 高的行（短码块 + 全称 + 色点）；
  点一行 = 打上，面板不关闭（可连点多个）。
  验收：从"看到题"到"打上标签" = **2 次点击**（号牌 → 标签），零输入。这是触屏上的硬指标。
- **U8** 面板标签区顶部固定一个「＋ 新建」行 → 展开输入框，回车即"新建 + 打上"（仍 2 次点击 + 打字）。
  新建标签自动进标签库（T4 不需要单独去"管理"页）。
  验收：输入"力学综合"回车后，本题短码出现、留白里更新、库中多一条。
- **U9** 同一题同一标签不重复（幂等）；再点一次 = 无变化不报错。**已打上的标签在面板里必须显示为选中态**（否则触屏上用户不知道打没打上）。
- **U10** 新标签短码自动取名字前 2 字，可在标签库里改；短码重复不阻止，但面板里两条必须靠全称可分。

### 改与删

- **U11** 摘除入口有两处，**面板为主**：面板里已选中的标签行再点一次 = 摘除（选中态即开关）。
  快捷方式（可选实现，非验收门槛）：**长按题号牌 500ms** → 快速菜单（`摘除本题全部标签 / 打开面板`）。
  桌面保留右键 = 同一快速菜单，但**不作为任何验收前提**。
- **U12** 「换标签」= 在面板里点掉旧的 + 点新的，不做专门控件；「摘掉此标签」只断本题绑定，**不删库里的标签**。
- **U13** 点题号牌打开的面板同时承载**既有详情**（题干/选项/配对答案，来自 `bank.json`）与新增标签区，
  不出现两个并存的浮层。详情区在标签区**下方**（拇指优先给动作，阅读内容需上滑）。
- **U14** 摘除不弹二次确认、不可撤销，但**必须在 200ms 内完成渲染并给出即时反馈**（短码块消失 + 轻震动 `navigator.vibrate` 可选），刷新后仍是摘除后的状态。
  触屏上"点了没反应"比"误删"更让人不安——反馈是这条的主要风险。

### 标签库

- **U15** 面板底部「管理标签库」→ 同风格的下半屏面板：改名、改短码、改色、新增、删除。
  删除 = 从库里移除并**级联摘掉所有绑定**，必须先显示"会同时摘掉 N 题的标签"再确认。
- **U16** 首次运行预置 5 个：`好`(好题) `改`(待改) `校`(已校对) `留`(留着组卷) `难`(偏题/难题)。
  验收：短码底色与石青(选择题)/朱砂(needs_review)/洋红(解析遗漏)/青绿(OCR 候选) 肉眼可分；
  在 iPad 室外反光下仍要能分（对比度 ≥4.5:1，色板从现有令牌取并**先量后定**）。
- **U17** 库里只存一份、绑定只存 tagId ⇒ 改名全局传播（所有题短码同步更新）。
- **U18** 库为空（5 个全删）时成品页照常渲染、面板显示「新建」行，不报错。

### 持久化

- **U19** 打标后刷新仍在、关浏览器重开仍在、**换一台设备（手机打完在平板上看）也在**——因为服务端文件是唯一真相。
  验收：打标 → `cmd+R` → 在；`data/out/tags/<docId>.json` 里有记录；换 iPad 打开同一 URL 也看到。
- **U20** 标签**绝不写入 `questions.json` / `stages.json` / `bank.json`**（可再生产物，写入即被冲，C3）。
  独立文件：`data/out/tags/library.json`、`data/out/tags/<docId>.json`。
- **U21** 重跑 `npm run stages:export` 后：能上的保留，**对不上的进 `stale` 不删**，面板顶部可见提示
  「N 条标签在当前快照里对不上题目」+ 展开列出（题号/页/当时题干首 12 字）。
  这是"不静默失败"用到**用户劳动成果**上：宁可显示"找不到它了"，不可悄悄少 3 个标签。
- **U22** 读不到标签文件（首次、`data/` 被清空）→ 成品页与现在**行为完全一致**，标签层为空、无报错、无空框、版式不变。
- **U23** 写入失败（磁盘只读/路径非法/离线访问）→ 面板显示失败原因并保持内存态，提供 JSON 文本复制出口。
  **不静默退化成 localStorage**（会造成"以为保住了"的假象）。→ 拍板 Q3
- **U27** 手机/平板可访问：`npm run view` 启动时**额外打印局域网地址**（枚举 `os.networkInterfaces()` 的 IPv4，如 `http://192.168.x.x:4173/final/?doc=…`），
  并把 `doc` 参数完整带上；文档说明首次访问需在 macOS 防火墙放行、且必须同一 WiFi。
  验收：iPhone/Safari 用打印出的地址打开成品页并成功打标（走通 `POST /api/tags`）。

### 边界与性能

- **U24** 跨页续段（`startsHere===false`，本卷 2 处）不挂号牌也不挂标签；标签只绑整题 `q.id`，在起始页显示。
- **U25** `stages/`「成品/对比」共用 `renderPaper` 自动获得标签层，但本期**只要求成品页验收**；`viewer/` 不做（§7）。
- **U26** 标签层新增节点 ≤ 本页题目数 × 5，且常驻层 `pointer-events:none` 不新增任何事件监听器（只在号牌上委托）；
  整册滚动在 iPad Safari 上无可感知掉帧。
  与 §6-7「大卷性能未验证」同一笔账：本期不解决，但**不得让它变差**，需报告节点增量与首屏耗时差。

## 5. 交互细节（触屏口径）

| 项 | 定值 | 为什么 |
|---|---|---|
| 面板形态 | **下半屏 sheet**（高 ≤60vh，可上滑到 90vh），非右侧抽屉 | 现有 `.fb-detail` 是 `right:0 / width:min(420px,92vw)`——手机上等于整屏宽但只占半屏，且详情在标签上方。T6 单手 + 打标动作优先 ⇒ 重排为下方进入 |
| 面板行高 | 每个标签行 ≥ **44px**（含 padding），库管理行同 | 触屏最小可点尺寸；面板在 `fixed` 层，不受纸面缩放影响 |
| 长按判定 | 500ms，位移 >10px 取消（视为滚动） | 短于 iOS 放大镜阈值会撞手势 |
| 系统手势抑制 | 号牌与标签层统一 `-webkit-touch-callout:none; user-select:none; touch-action:manipulation` | 否则长按先弹「拷贝/查找」，快速菜单出不来 |
| 号牌热区 | 视觉不变（15×14px），热区扩到 **44×44**（`::before`，不改布局、不吃 `innerW`） | 纸面唯一 tap 目标必须点得准；留白内没有别的可点物，扩了也不碰碰撞 |
| 缩放关系 | 常驻短码随纸面缩放（可能小到看不清 → 靠面板里 44px 行兜底）；面板字号固定 | 用户放大读题时短码自然变大，缩小时动作仍在面板里，两不干扰 |
| 键盘 | 新建标签输入框 `font-size ≥16px`，聚焦后滚动进可视区，用 `visualViewport` 调整面板高度 | iOS 上 <16px 输入框会**自动放大整页**；键盘弹起会顶掉 `fixed` 面板 |
| 浮层位置 | 一律 `fixed`，绝不进 `.canvas` | 解 C2（`overflow:hidden` 会裁）且不碰版式 |
| 关闭 | 点遮罩 / `Esc`（桌面）/ 下拉手势或面板「完成」按钮（触屏） | 触屏必须有明确关闭按钮 |
| 命名 | 新类一律 `.qtag*`（`.qtag` / `.qtag-more` / `.qtag-sheet`） | **`.tag` 已被占用**（OCR 角标 `stages.css:340`、丢弃块角标 `:403`），复用必串台 |
| 遮挡判定 | 任何"是否压正文"判断，先把 Range 矩形**垂直收到 `font-size`** 再判 | 红线 G9：DOM 矩形高 ≈1.4em 是字体盒不是墨迹，直接用会把正常行距判成叠字 |

## 6. 数据模型

```jsonc
// data/out/tags/library.json —— 全局一份（分卷与否见 Q4）
{ "version": 1,
  "tags": [ { "id": "t:good", "name": "好题", "short": "好", "color": "#2f7d5b", "createdAt": "..." } ] }

// data/out/tags/23必刷题 2相互作用.json —— 每卷一份，文件名 = docId
{ "version": 1, "updatedAt": "...",
  "bindings": [
    { "questionId": "23必刷题 2相互作用:p0:q0",   // 主键，来自 stages.json 的 q.id
      "tagIds": ["t:good"],
      "anchor": { "number": "1", "page": 1, "section": "第1节 重力 弹力 摩擦力",
                  "firstText": "[广东广州2022月考]如图" } }   // 题干首块前 16 字，供 U21 漂移核对
  ],
  "stale": [] }   // 对不上时由 U21 填入，人工处理前不删
```

- **绑定键 = `q.id`（`docId:p<page>:q<seq>`），并接受其已知脆弱性**：位置型 ID，切分一变就漂移。
  缓解 = 存 `anchor` 快照 + U21 可见化；**不做自动重定位**（重定位是启发式搬迁，红线 G6 要求判据取最严且有独立分母，本期没有）。
  更稳的 `bank.key`（`chapter|blockIndex|number`，可跨题册/答案册同步）见 Q5。
- 绑定与库**分离**：改名只动 library，摘除只动 bindings（U12/U17 成立的前提）。
- 写入：`POST /api/tags?doc=<docId>`，body 为整个文件 JSON，服务端全量覆盖（单用户，无并发合并）。

### 写通道安全口径（本项目第一条写路径，一次做对）

1. `doc` 只能取白名单：与服务端一份 `DOCS` 常量同源（`final.js` 的 `DOCS` 与之互校），或校验 `data/out/<doc>/stages.json` 存在；
   拒绝含 `/`、`\`、`..`、控制字符、超长的输入。
2. 落盘路径服务端拼接 `data/out/tags/<doc>.json`，**不接受客户端传路径**；`normalize()` 后断言仍以 `<ROOT>/data/out/tags/` 起头。
3. body 大小上限（2 MB）+ `version` 校验，非法一律 400 且不写盘。
4. **先算完整内容再 `open('w')`**（既有教训 `feedback-scripted-writes-and-claim-evidence`），失败不留半截文件。
5. 静态读白名单不变；新分支只接 `POST /api/tags`，其余按现状（不把 `/data/out` 变成可写区）。
6. 局域网暴露 = 同一 WiFi 内任何人可读可写这台机器的标签文件——**本地开发工具的既定取舍**，需在文档写明；
   不提供鉴权（本期），但**不得**因此扩宽任何其它路径的可写性。

### 截图审板又抓到的三个缺陷（程序化门都看不见）

| 症状 | 根因 | 为什么机器门漏过 |
|---|---|---|
| 面板「新建标签」输入框一直开着 | `.tag-new-form{display:flex}` 顶掉了 `hidden` 属性的 UA 规则 | DOM 里 `hidden=true`、几何不压正文、版式哈希不变——只有眼睛看得出"它不该在" |
| 面板底部一条空的米色框 | 无漂移条目时仍 append 了带边框的空 div | 同上（空框不是"内容缺失"，任何齐全性断言都不报） |
| **点题目看答案没有图片**（用户报的） | 面板一直在读 `stages.json` 的题目对象，而那里没有 `stem/options/images` ⇒ 题干此前渲染成 `undefined`、选项恒 0 | 图片是**新增内容**，纸面几何不变、审计哈希不变 ⇒ 版式门天然管不到；要管的是**内容来源**，见 DECISIONS §32 |

⇒ 结论写在这：**「版式不变」的门与「内容齐全」的门是两回事**，前者绿不代表后者绿。
