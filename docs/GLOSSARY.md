## A. 坐标与墨迹

### 墨迹带 = 页图横着切，有墨的地方连成一条带，拿来当「字在哪」的真值

```
原卷页图（灰度）          横切投影               墨迹带
┌─────────────┐      每一行有多少墨点        ┌─────────────┐
│ 第一行字 ███ │      ───────────────►       │ ▓▓▓▓▓▓▓▓▓▓▓ │ ← 带1
│             │      有墨=高，空白=0         │             │
│ 第二行字 ███ │                             │ ▓▓▓▓▓▓▓▓▓▓▓ │ ← 带2
└─────────────┘                             └─────────────┘
```
- 为什么用它：MinerU 给的坐标会漏行；墨迹来自原卷像素，不依赖解析，所以当真值。
- 出处：`docs/DECISIONS.md §110`（V3 行框 ↔ 墨迹配对）。

### 配带率 = 一行字成功配到墨迹带的比例

```
某页 100 行 ──► 89 行配上了带、11 行没配上（noBand）
配带率 = 89/100 = 89%
```
- 「低配带率页」= 很多行没配上的页，通常就是密集页。
- 出处：`docs/BACKLOG.md L-11`（本地全册 79%，剔网格页 82.4%）。

### 行框 / 本地 V3 = 本地 OCR 产线给的「这一行在哪个矩形」

- 本地 V3 = 局域网 4070 笔记本上跑的 PP-StructureV3，产出**行框**（行级矩形）。
- 它只给「在哪」，不给「是什么字」；字由 OXR 读。行框再去**吸附**到墨迹带上对齐。
- 注意：字级框（每个字的框）这条流水线**不产出**。
- 出处：`docs/BACKLOG.md L-10`；记忆 `reference-lan-laptop-local-ocr`。

### OXR / 换源 = 读字引擎；把 MinerU 一身兼两职拆开各自换

```
老架构：MinerU 既读字又给坐标 ──► 但它漏行
新方案：读字（内容）──► OXR              不漏行
        定位（坐标）──► 墨迹带 + 本地 V3 行框
```
- 换源探针结论：OXR 漏行 14/14 全救回、新造漏行 0/286（双向完美）。
- 出处：`docs/DECISIONS.md §59`（文字用 OXR）、`docs/BACKLOG.md L-13`。

## B. 补洞与判据

### 洞 = 页面上有墨、但解析没盖住的一小块区域

```
┌─────────────────────────┐
│ 解析盖住的字 ███████████ │
│ ░░░░░  ← 洞：有墨，解析没盖 │
│ 解析盖住的字 ███████████ │
└─────────────────────────┘
我们想拿 OCR 读出的文字去「补」这个洞。
```
- 出处：`scripts/ocr-page-fill-jobs.ts`（补洞流水线）。

### judgeHole = 决定「要不要拿这段 OCR 文字补这个洞」的函数

它一次查好几条判据，全过才补：文字非空、公式 `$` 成对、宽度比合格、洞够大、与裁图一致、**不重复（dup 门）**。
- 出处：`scripts/ocr-page-fill-jobs.ts:209`。

### dup 门 / 重复防护 = 补洞前查「这段字是不是页面上早就有了」

```
OCR 候选文字 ──► 切成 4 字一组 ──► 跟「整页 MinerU 已有文字」比
                                        │
                        ┌───────────────┴───────────────┐
                   ≥85% 已经有                      <85%
                        │                               │
                  「这是把已有的字                  「真是上游漏的字」
                   重复塞进洞」⇒ 拒补                 ⇒ 允许补
                  （不是漏识别，是配错行）

阈值 DUP_RATIO_MAX = 0.85
```
- 为什么需要：p91 h0 实测过一种错配——把页面别处已有的字误配进洞。dup 门就是拦这种。
- 关键短路：`const notDup = !pageText || dup < 0.85`。**只要传进来的整页文字是空，门就直接放行**。
- 出处：`scripts/ocr-page-fill-jobs.ts:72`（阈值）、`:75`（dupRatio）、`:227-228`（短路）。

### B-37 = dup 门「生产关着、文档说开着、直读路误拒 4 洞」的不一致

```
同一个安检，两条路一个关一个开
══════════════════════════════════════════════════════════

生产补洞路（ocr-page-fill-jobs.ts:568 / 576 / 612）
   传给安检的「整页文字」= undefined（空）
      ⇒ !pageText 为真 ⇒ 安检直接放行 ⇒ 门实际关着
      ⇒ 但函数文档(:204-208)还宣称门开着 ⇒ 文档与行为不符
   （:471 算了 pageMinerUText 却没传进去 = 死变量）

直读洞路（hole-read-judge.ts:54 / 57）
   传的是真·整页文字 ⇒ 门开着
      ⇒ 4 个真洞被误拒：p091_h2 / p159_h1 / p023_h1 / p023_h4
         裁图墨迹与 recText 逐字吻合、MinerU 同文块都在洞远端
         ⇒ dup=1.00 在这条路不代表「配错行」
         ⇒ 门的语义只对「配对路」成立，直读路不该照搬

修复方向（都待拍板）：
   ① 生产三处传真 pageText（行为变更，需拍板）
   ② 更正函数文档串
   ③ 直读路按语义分流（别套用配对路的门）
```
- 一句话：**B-37 dup 门修复 = 把「这个防重复安检到底该不该开、在哪条路开」弄一致**——现在生产偷偷关着、文档谎称开着、另一条路却开着还误伤了 4 个真洞。
- 出处：`docs/BACKLOG.md B-37`；代码见上。

## C. 密集页与修复

### 密集页 / noBand = 行很密、很多行配不上墨迹带的页

- noBand = 「没配到带」的行。密集页（如 p76/p127）noBand 特别多。
- 出处：`docs/BACKLOG.md L-14`。

### 插图巨带 = 插图被当成一个巨大的带，把里面的行整个吞进去

```
正常文字带：一条带 ≈ 一行字
插图巨带：  一整块插图被当成一条超高带
            ┌───────────┐
            │  插图      │ ← 一条带吞掉几十行
            │  (表格/图) │
            └───────────┘
```
- 这是密集页 noBand 的**主因**：p76 43/89、p127 70/86，两页合计 113/175。
- 不是「缝阈值」问题——降阈值治不了它。
- 出处：`docs/BACKLOG.md L-14 / B-38`。

### exempt / mbl = 两个开关（都在 ink-band-align.ts）

```
mbl（maxBandLines）= 一条墨迹带最多能吸几行
   默认 3 ──► 试到 5（mbl5）：让原本被砍掉的行有机会保留

exempt（bandExemptFullyOverlapping）= 放行不截断
   对「完全重叠、又不太高（带高 ≤ 1.6× 行高中位）」的带，不砍行
   默认 false（关）──► 小试时打开
```
- 收益（小试）：p76 +44 行、p127 +21 行（含 mbl5）。
- 风险：mbl8 历史教训——增量 74% 是跨行垃圾 ⇒ 要小试对照，别全量。
- 出处：`scripts/ink-band-align.ts:26`（MAX_BAND_LINES=3）、`:30`（1.6）、`:273-274`（默认）。

### audit-gap-roots = 逐页诊断「这些行为什么没配上」的本地命令

- 把 noBand 的行分四类：插图巨带 / 单行拆多框 / 零白缝 / 公式小缝。
- 零 API（全本地，不烧配额），可逐页只报警复跑。
- 出处：`scripts/audit-gap-roots.ts`；`docs/BACKLOG.md L-14`。

### 救回行有效率 / 跨行垃圾率 = 小试的两个判据

```
救回行有效率 = 救回来的行里，真正对的占多少   （越高越好）
跨行垃圾率   = 误吸进来的邻行垃圾占多少       （越低越好）
```
- 用来决定「exempt+mbl5 这套设置能不能转生产」。
- 出处：`docs/BACKLOG.md B-38`。

### B-38 = 密集页修复项（插图框识别 + 容量按视觉行计）

- 依据 L-14：先认出插图/表格框、专属切带；单行拆多框类可用现成 exempt 旗标治。
- 转生产 = 行为变更需拍板；先小试 + 对照，不全量。
- 出处：`docs/BACKLOG.md B-38`。
