# 题库查看器（Viewer）前端产品需求文档（PRD v1）

> 适用范围：question-seg-engine 切片的展示层独立模块。
> 用途：作为 Google Stitch（或任何 UI 设计工具/AI）的设计输入稿；Stitch 生成设计稿后，以本文件为准进行评审对齐。
> 状态：待设计验证。配套技术契约：`viewer/docs/CONTRACT.md`（跨层边界，UI 设计不违背该契约）。

---

## 1. 产品概述

一句话：**把 PDF/图片里的高中试题，在浏览器里以「试卷纸面」的形态重新呈现，供老师/运营审校与浏览的结构化题目查看器。**

背景：上游引擎（MinerU → 双栏还原 → 结构化切分）已能把真实样卷（如《23 必刷题 2 相互作用》，15 页、85 题）转成结构化题目——题干、选项 A-D、附图、答案、题型、置信度。当前缺失的一环是"看得见"的展示层：本产品即该展示层，作为独立模块存在（消费固定 JSON 契约，将来可整体替换/嵌入宿主应用）。

产品设计基调（已定，可微调）：**「编辑部印刷物」**——把屏幕当作一张试卷排版台。不是常规的"后台管理列表"，而是一间安静、挪味的编辑部里摊开的校样。

---

## 2. 目标用户

| 用户 | 画像 | 核心诉求 |
|------|------|----------|
| **出题老师 / 教研员**（主用户） | 使用切片引擎扫描整本教辅，浏览整理题目入库 | 快速判断"这道题切得对不对、题干选项完整吗、图对不对"；把好题挑出来，坏题标出来 |
| **题库运营 / 审校员** | 批量处理质检队列（needs_review 题目） | 一眼看到哪些题需要人工订正；在题面上下文中完成校对 |
| **备考学生**（次用户，浅层场景） | 老师分享的题目链接 | 在手机上像做纸质练习卷一样做题、对答案 |
| **技术接入方**（约束型用户） | 宿主应用开发者 | 展示层遵守数据契约、职责单一、可替换（非界面设计对象，但影响边界设计） |

## 3. 核心使用场景（U1-U4）

- **U1 · 切分质量验收（最高频）**：跑完解析管线，打开查看器核对整卷——85 题里 83 题可用，聚焦 2 题 needs_review 逐题订正。用户期待：一屏扫完 15 页试卷的结构化成果，问题题与正常题一眼可分。
- **U2 · 结构化浏览与检索**：按大题（一、选择题 / 二、解答题…）浏览题目流；筛选题型（选择/主观）；快速定位"某题号第 N 题"。
- **U3 · 纸面做题体验**：隐藏答案的题目像真实试卷——可先看题、思考，再揭晓答案（默认隐藏答案，开关揭示，符合教育场景的"先做再看"）。
- **U4 · 审校与标记（预留浅层）**：在题目上下文中标记"此题需修正 / 备注原因"——本版本先做只读展示 + 状态呈现，标记动作留接口（不作为 v1 强制）。

| # | 页面 | 核心用途 |
|---|------|----------|

## 5. 每页面的模块结构

### P1 题库总览页

```
┌──────────────────────────────────────────────────────────────────┐
│ 顶栏：产品名·试卷标题(小字号)│ 统计条(85题·83ok·2审) ·筛选(题型) ·答案开关 │
├────────────┬─────────────────────────────────────────────────────┤
│ 目录栏 240px│  页眉：大题进度(n/m)＋细线下划线标题                    │
│ (深墨底)    │                                                     │
│ ▸ 一、选择  │  ┌─ 题目卡片（A4 纸张模型，宽 794px）───┐              │
│   1 ○      │  │ [题号+题型徽+状态点] [题干(公式渲染)] │              │
│   2 ○      │  │ [附图]  [选项 A·B·C·D]              │              │
│   3 ●(审)  │  │ [答题区：按题型留白的虚线空栏]        │              │
│ ▸ 二、解答  │  │ [答案区：默认隐藏 ▸ 开关揭示]         │              │
│   4 ○      │  └───────────────────────────────────┘              │
│ …          │                                                     │
└────────────┴─────────────────────────────────────────────────────┘
```

- **顶栏**：产品名「试卷编辑部」式标题 + 试卷名；统计条（题总数 / ok / needs_review，needs_review 用警示色）；题型筛选（全部/选择/主观）；**全局答案开关**（默认关）。
- **目录栏**（sticky，深墨底）：按 `section`（大题）分组；每组下行条目 = 题号 + 状态色点（ok=灰蓝、needs_review=朱砂）；点击锚点平滑滚动到该卡；滚动时当前题高亮。
- **题目卡片**（核心组件，全站复用）：题头（题号原文 + 题型徽标 + 状态点）；题干（`$..$` 公式 KaTeX 渲染）；附图（若题有图，等比适配卡片宽）；选项（choice 型 A-D 竖排）；**答题区**（无内容，虚线铺底，高度按题型——选择题 0px、主观题 ≈378px 对应 A4 纸上 10cm）；**答案区**（答案值 朱砂红 + 解析墨黑小字，默认隐藏）。
- 卡片流左对齐、非对称，加载时 stagger 渐显（每卡延迟递增）。

### P2 单题审校页

```
面包屑: 试卷名 / 大题 / 第 N 题
┌──────────────────────────────────────────────┐
│ 侧列（240px）：原卷页码·块序号·置信度·状态      │
├──────────────────────────────────────────────┤
│  A4 纸卡（放大）：题干/公式/大图(Lightbox)      │
│  ───────── 虚线答题区 ─────────               │
│  答案区：【揭晓答案】按钮 → 朱砂红答案+解析     │
│  底部操作条：上一题/下一题 · 标记(预留)         │
└──────────────────────────────────────────────┘
```

### P3 质检队列页

```
顶栏(复用) + 过滤条件（全部待审 / 仅缺选项 / 仅低置信度 — 预留）
列表：精简卡片（错误摘要·置信度·位置 p8·触发行摘录）
每项动作：打开单题审校 / 标记已处理(预留) / 忽略(预留)
空态：✅ 全部审毕 —— 朱砂红对钩大图 + 文案
```

### G1 全局能力

- **全局答案开关**：P1 顶栏 / P2 单题 / P3 列表项内各自的开关，且互相同步（P1 打开 → P2 进入即展开）。
- **数据源切换**：URL 参数 `?doc=<docId>`（默认 `23必刷题 2相互作用`）；无参数或参数无效 → 进入加载失败空态（见 §8）。
- **快捷键**：`A` 切换答案、`N/P` 上下题、`1/2/3` 切页（桌面端加分项）。

## 6. 视觉风格关键词

- **编辑部印刷物（Editorial print）**：纸感、排版、印章，拒绝"通用后台"感
- 配色：**米纸底 `#F6F1E7` · 墨黑 `#24272B` · 朱砂红 `#B03A2E`（答案/警示/印章）· 灰蓝 `#44627A`（元数据）· 米灰 `#CFC5B2`（分隔/虚线）**
- 字体：正文**宋体系**（Source Han Serif SC / Noto Serif SC / Songti SC，serif）；数据/题号/标签用**等宽 mono**；标题同字体族加粗、字距拉开
- 布局语言：**非对称分栏**（左深色目录 + 右纸面流）、纸张模型（A4 宽高比）、虚线答题栏、答案揭晓用**印章式偏移叠块**（红描边、错位 4px）
- 动效：**克制**——卡片 stagger 渐显（页载一次）、答案区淡入、目录高亮过渡；不做花哨动效
- 图标：内联 SVG 线条图标（书/眼/对钩/警示），单一线宽、与墨色统一

## 7. 交互设计要点

| 交互 | 行为 |
|------|------|
| 答案开关 | 默认全局隐藏；点击任一开关 → 该题/全部答案区淡入展开；再次点击收起；状态持久到当前会话 |
| 目录锚点 | 点击平滑滚动；滚动时 IntersectionObserver 高亮当前题；目录 sticky |
| 题型筛选 | 顶栏三态（全部/选择/主观）；切换后卡片流过滤、统计条同步 |
| 图片 | 惰性加载（loading=lazy）；点击 → Lightbox 全屏等比查看（移动端全屏）；加载失败显示米灰占位符 |
| 公式 | KaTeX auto-render；长公式卡片内横向滚动（不破布局） |
| 审校动作（预留） | 卡片/队列页出现「标记」入口（按钮位预留，v1 仅展示状态不落库） |
| 快捷键（桌面） | A/N/P/1/2/3 |

## 8. 空状态 / 加载状态 / 异常状态

**加载**：
- questions.json 拉取中：目录栏 + 卡片区**纸张骨架屏**（纸白块 shimmer，3-5 张）
- 图片：lazy + 米灰占位底，load 后淡入
- KaTeX CDN 未就绪（离线）：页面可正常阅读，公式以 `$..$` 原文显示，顶栏小字提示「公式渲染组件未加载」

**空状态**：
- 无数据（docId 不对 / 尚未跑管线）：居中纸面卡片 + 文案「此卷还没有解析产物——先运行 npm run view 或检查 docId」+ 操作按钮（回默认卷）
- 筛选无结果：目录栏正常，卡片区显示「没有符合筛选的题目」+ 重置筛选按钮
- 无附图题目：卡片正常（图区不占位不破版）
- 无答案题目：答案区显示「—」（灰蓝小字），开关不误报

**异常**：
- JSON 结构不符合契约：顶部警示条「数据版本与契约不符（详见 viewer/docs/CONTRACT.md）」，仍尽力渲染可用字段
- 网络中断/服务器未起：加载失败页 → 重试按钮

## 9. 移动端适配（≤768px 优先）

- **目录栏 → 顶部抽屉**：528px 以下目录栏收进顶栏汉堡按钮（左滑抽屉，半屏遮罩），当前题高亮逻辑不变
- **纸张模型降级**：卡片不再硬性 794px，改为流式宽度（padding 16px）；答题区留白**按比例缩放**（主观题 378px → min(378px, 28vh)），A4 语义保留但不再字面模拟
- 触控：所有可点击目标 ≥44×44px；答案开关为整行可点
- 图片 Lightbox 全屏；公式横向滚动保留（触控自然滚动）
- 顶栏压缩：统计条折叠为「85题·2审」徽标，筛选收入溢出菜单
- 字体：正文不小于 16px；行高 1.8（中文长题干可读性）

## 10. 验收口径（供 Stitch 设计稿评审时对照）

1. 三区结构（试题区/答题区/答案区）在任何设计稿中可辨认
2. 答案默认隐藏、开关可见且状态可感知（全局/单题两级）
3. needs_review 题目在总览流中一眼可辨（色点/徽标）且可直达审校
4. 视觉五要素（纸底/朱砂/宋体/非对称/印章式答案）齐全，无泛化 AI 感
5. 三种状态（加载/空/异常）在设计稿中有对应画面（至少加载骨架与空状态）
6. 移动端至少一张代表稿（目录抽屉或纸张降级形态）
