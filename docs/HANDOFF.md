## 1. 项目是什么（30 秒版）

MinerU 解析结果（`layout.json` 优先，`content_list.json` 退化路径）的**后处理层**：
把一份试卷 PDF 的结构化解析输出，切成「题干 / 选项 / 答案」齐全的题目 JSON。

```
layout.json / content_list.json
   │ normalize.ts    与上游唯一耦合点（换解析供应商只改这里）
   ▼ ParsedDocument
   │ layout.ts       版面层：分栏检测 + 阅读顺序恢复（只认坐标，不认语义）
   ▼ 阅读顺序块序列
   │ patterns.ts     语言层：题号/选项/大题/答案区模式（只认文本形状）
   │ rule-engine.ts  有限状态机切题 + 置信度 + ReviewNote
   ▼ validation.ts   回拼校验（所有策略强制出口）
   SegmentationResult { questions, reviews, stats }
```

- 技术栈：TypeScript ESM、`node:test`、tsx；**零运行时依赖**（devDeps 仅 adm-zip/tsx/typescript）。
- 定位：垂直演进模型起点，代码是生产级姿态。

## 5. 红线（违反任意一条 = 破坏项目根基，勿以「优化」之名绕过）

1. **不静默失败 / 不丢内容**：低置信度必须 `needs_review` + `ReviewNote`。任何「丢弃/搬迁/改写」
   之前先问：**这是噪声，还是我没认出来？** 后者要还原或保留可见，不能删。
   历史翻车：把 MinerU 认错的上标 2 当噪声丢弃 → 平方消失；臆想原卷连写而收紧数学空格 → 回原卷发现原卷本身有空格。
2. **展示层任何美化必须先回原卷页图核对**（`data/out/<docId>/pages/`），不能凭推断。
   判据宽度比是相对量，对「同宽的错文本」不敏感（4 次串位每次都「合格」）—— 必须交叉核对 + 形状前置条件 + 逐条回原卷。
3. **检测不改写**：`src/formula.ts` 只统计不改数据；数据清洗必须是显式独立决策。
4. **解耦**：`viewer/`、`stages/`、`final/` 只消费快照（questions.json / stages.json），不 import 引擎 `src/`；
   唯一可 import 引擎代码处是构建期脚本 `scripts/export-stages.ts`。
   **纸面重建只此一处实现**（`stages/reconstruct.js` 的 `renderPaper`）—— 成品页与 stages 的
   「成品/对比」共用它；再写第二套 = 必然漂移（字号口径/留白/号牌落位任一处改了另一处不知道）。
5. **验收方法**：显示层/算法修复的验收 = **文本全量清点**（逐块独立匹配，不拼接）+
   **逐页截图视觉审板**，两条全量跑；审板清单第一项永远是「**内容齐全性**」，
   清单来源是红线而非本轮改动；覆盖面的漏检与粒度的漏检同样致命。
6. **启发式形状判据取最严**：「搬迁/丢弃」类规则判据用 AND，必须同页守卫 + 产出可核对记录；
   回归验收必须包含「它当初要修的那个案例仍成立」。
7. **审计判据与实现不同源**；判据的分母必须来自被检验对象之外的独立来源（原卷页图/OCR）——
   否则「覆盖率 100%」是循环论证（被漏项既不在分子也不在分母）。
8. **`0` 永远不是题号**（题号域首位 `[1-9]`，`src/patterns.ts` 三处同步）；残留缺口：`1.$5` 仍会被判成题号 1。
9. **判遮挡一律用墨迹口径**（蒸馏自 `.workbuddy-ai/memory/`，2026-10-10 两次踩坑）：
   `Range.getBoundingClientRect()` 的**高是字体 ascent/descent（≈1.4em），不是墨迹** ——
   拿它判「文字是否压到别人」会把正常行距（1.2em）误判成叠字（Task 3/6 与 10-10 各踩一次）。
   正确做法：CJK 墨迹高 ≈ 1em，判之前先把 Range 矩形**垂直收到 `font-size`** 再判。
10. **「用户看得见」按他打开那一屏判，不按 DOM 判**（2026-10-15 同一件事返工两次）：
    面板 `.fb-detail` 是**定高滚动容器**（视口 850px、内容动辄 1486px、打开时 `scrollTop=0`）——
    东西挂在裁切图下方 = 挂在折叠线以下，量得到、DOM 里有、**屏幕上没有**。
    三条硬规矩：① 提示类文字放在它要解释的图**之前**，不放之后；
    ② 验收必须**在默认滚动位置截图**，不许先 `scrollIntoView` 再截图；
    ③ dpr=2 的截图回传时被降到 50% 显示 ⇒ 10px 级的小标记"看着像有"是假象，
    要么量数（尺寸/余量），要么放大倍数看，别信缩略图。

## 7. 新接手者的前 30 分钟

1. 读根目录 `AGENTS.md` → 本文件 → `README.md`。需要设计/口径依据时再按 §4 取 `DECISIONS.md` 对应章节。
2. `npm install && npm run check` —— **必须全绿才能动手**；不绿先修门，勿带病开发。
   ⚠️ **新建/换 worktree 时门会红 2 例**（`tests/contract*.test.ts` 读
   `data/out/23必刷题 2相互作用/questions.json`）：`data/` 是 git 忽略的运行时产物，
   新 worktree 里没有。不是代码缺陷 —— 在 worktree 根目录
   **`cp -Rc <主仓库>/data data` 做 APFS 克隆**（秒级、写时复制不占双倍空间；
   ⚠️ 不要用软链：两个 worktree 会共用同一个产物目录，并行会话互相覆盖，
   见 `tasks/lessons.md` L4），或用 `npm run daily` 重新生成。
   `books/` 是只读源 PDF，保持软链共享即可。判据：这 2 例之外的任何红都是真红。
3. 先看**成品页**（`npm run view` → `/final/?doc=<docId>`）：这就是交付物的样子，
   逐页按原坐标重建、像翻原版书。再看 `npm run stages` 的**对比模式**
   （`?doc=第二章相互作用-答案与解析`）对照原卷页图看 5 分钟——建立「这套系统现在长什么样」的直觉。
4. 认领任务前：先查 §6 是否已有登记，避免重复立任务；改动遵循 §5 红线。
5. 声称「完成」的条件：质量门全绿 +（显示层改动）全量截图审板过 + 文档按 §4 归属更新。
   **「后台数字达标」≠「页面上看得见」≠「看得见就一定没被裁切」—— 截图必须覆盖目标区域。**
