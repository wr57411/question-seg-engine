# 整页补字：VL 出字 + V3 出行框（小样方案 v1，2026-11-03）

> 状态：**方案 + 小样探针**，未改产线。产线改动以本文件第 6 节的验收为准。
> 背景证据：`docs/evidence/2026-11-03-paddle-two-routes-probe.md`（VL 块级 / V3 行级，13 本 24,326 行框）、
> `docs/DECISIONS.md §107`、`§108`（可核验性三档）。

## 1. 要解决的问题

上游解析（MinerU）整行漏读时，现在用整页 OCR 的文字去补。旧通道只给**纯文本**，
于是 `scripts/ocr-page-fill.ts:468-489` 把文字**按洞宽等比例摊**回纸面 —— 位置是猜的。
V3 给**行级框**（`overall_ocr_res.rec_polys`），VL 给**更准的文字**（页图核过 0/23 真错 vs V3 8/27）。

## 2. 一句话方案

**文字取 VL，位置取 V3；行与行靠文字锚点匹配，锚不上的整行用排除法定，连续失配交人工。**

## 3. 算法（逐页、逐 VL 块）

1. **候选行**：取 V3 行框中**中心点落在该 VL 块框内**（块框外扩 0.002 页宽/高）的行，按 (y, x) 排序。
2. **硬归一化**：两边都去掉空白与 `$ \ { }`（与 `ocr-page-fill.ts:hardNorm` 同口径）。
3. **锚点链**：按行序在块文本里**单调向前**搜该行文本；搜到即锚定，游标前移。
4. **排除法**：两个锚点之间（或首尾）若**恰好剩 1 行**，且该区间**有剩余文字** ⇒ 该行就是这段文字。
5. **交人工**：同一区间剩 **≥2 行**且都有剩余文字 ⇒ `needs_human`，不猜。
6. **闸门按「缺口」算，不按整块算**（2026-11-03 用户定）：只挡**真正没落位的那几行**，其余照补。
   原来的「整块未消费完就整块不补」改成：逐缺口判定 —— 已锚定的行照常补，未落位的行标 `needs_review`。
7. **表格只标那一格**（同日用户定）：单元格对不上时只标该格，不把整张表打成待核。

### 3.1 残余风险（用户决定带来的，必须补守卫）

闸门按缺口算之后，**原来"V3 漏行 ⇒ 整块不补"的那层保护没了**：一块里其他行锚得好好的，
只剩一个缺口时，排除法会把这段文字塞给缺口里唯一那条线 —— 即使那条线其实是 V3 漏读后
错位的邻行。**此时不会报警**。

⇒ 建议给排除法加**几何守卫**：只有当「该行框的高×宽」放得下「缺口字数×字号」时才允许排除法落位
（复用 `ocr-page-fill.ts` 的 `MIN_EXPECT_CHARS` 同口径思路）；放不下 ⇒ 该行标 `needs_review`，不填。
状态：**已定并已实现**（2026-11-03 用户定）：加守卫，阈值 **1.5 倍**。
尺子不用字号（字号是整页中位行高、字宽也不齐、LaTeX 记号纸面上不存在 ⇒ 绝对量估不准），
改用**同块已锚定行的平均每行字数**；缺口超过它的 1.5 倍 ⇒ 不填、标待核。
一块里一个锚都没有 ⇒ 无从校准 ⇒ 也不填。

实测（守卫上线后，三本）：`text` 块自动定行 **92.4% / 93.6% / 90.5%**，
守卫拦下 1.0% / 2.3% / 3.5%——拦得不多，但把"漏行时静默塞错"这条路堵住了。
代价照实记：电路的整体自动定行从 93.1% 掉到 88.8%（守卫拦下 4.0%），这是买保险的钱。

## 4. 为什么这条链路不会静默失败

| 失效模式 | 现在的表现 |
|---|---|
| V3 行框漏了一行 | 排除法会把邻行文字塞进去，但**必然留下剩余文字** ⇒ `leftover_text` 报警 |
| 连续两行都是公式（都对不上） | 同一区间 ≥2 行有字 ⇒ `needs_human` |
| V3 某行字读错（`保`→`R^1`） | 只影响那一个锚点，邻居仍能锚；区间里恰好 1 行时由排除法接住 |
| VL 把两行并成一行 | 该块剩框 ⇒ `leftover_frame` 报警 |

## 5. 明确不做

- **不替换** `ocr-fill.ts`（裁图路径）；本轮只动整页路径。
- **不把 V3 的文字写进任何产物**：V3 只提供几何，字一律来自 VL。
- **不在失败时退回"按宽度摊"**：失败就标 `needs_review`，现状逻辑保持默认关闭（`DECISIONS §91`）。

| 指标 | 数 | 占比 |
|---|---:|---:|
| V3 行框（落在 VL 块内） | 1360 | 100% |
| 靠文字锚点定行 | 1173 | 86.3% |
| 靠排除法定行 | 93 | 6.8% |
| **交人工（区间有歧义）** | **18** | **1.3%** |
| 剩框报警（有框没字） | 35 | 2.6% |
| 剩字报警（有字没框，按缺口计） | 413 | — |
| 行框归块覆盖率 | 1736 / 1749 | 99.3% |

按块类型：`text` 自动定行 **94.1%**、`paragraph_title` 100%、`figure_title` 100%、`table` 91.0%、`chart` 76.1%。

**第一版只有 48.9%，修掉两个真因后到 86.3%（text 块 94.1%）**：
1. **全角/半角标点不一致**（VL 出 `,`、V3 出 `，`）⇒ 匹配前剥标点（`matchChars`）。
2. **行序 ≠ 文本序**（块内跨栏/跨页续段）⇒ 严格单调游标会把后面整段带崩；改为「先顺序找、找不到再从头找（记乱序）」并对已占用区间查重。

**仍不理想的地方（如实记）**：文字消费率 70.4%（text 块 76.7%）。差的主要是三类：① VL 块里的 markdown/HTML 记号（表格块最重）；② V3 召回漏掉的行；③ 空 `block_content` 的块（实测存在）。这三类都会落到 `剩字报警`，**不会静默填错**。

## 9. 剥掉标记后再测（2026-11-03 补）

表格块的 `block_content` 是 HTML，`<table><tr><td rowspan="2">` 这些**标签名**会被当成"没消费掉的字"。
`stripMarkup()` 先剥三样：HTML 标签、图片占位符、LaTeX 环境壳（`\begin{…}` / `\end{…}`）。

| 册 | 剥之前 | 剥之后 | 分母变化 |
|---|---:|---:|---:|
| 物理_教材基础练 电路 | 70.4% | **76.4%** | 13511 → 12440（−1071） |
| 23必刷题 2相互作用 | 93.0% | 93.0% | 16884 → 16874 |
| 第二章相互作用-答案与解析 | 90.2% | 90.2% | 48442 → 47704 |

**结论要更正一句**：标签只解释了电路差距的一部分（+6.0pp）。剩下的 76.4% vs 93% 是**真差异**——
V3 在表格里读的格子文本与 VL 的 HTML 文本在**切分与顺序**上不同（合并单元格、行列次序），不是标记噪声。
⇒ 表格继续走单元格通道（`table_res_list`），不指望行对齐能把表格这块拉平。

## 10. 洞内切行：用像素投影，不用模型（2026-11-03 用户提的思路，已实测）

`scripts/ink-lines.ts`：复用现有 `renderGrayPages`（pdftoppm -gray）+ 灰度阈值，
在洞的 bbox 内做**水平投影**（每行数墨迹像素），白缝处切开就是行；窄缝（<4px，上下标/分式横线）
合并。**零新依赖、零模型调用、可离线复跑。**

《电路》实跑（13 页，150dpi）：content 且宽高比 ≥1.5 的洞 **273 个**

| 观察 | 数 | 含义 |
|---|---:|---|
| 切出 1 行 | 272 | **洞基本就是一行高** ⇒ 「按洞补」的位置是完整的，不是"第一行最左点" |
| 切出 ≥2 行 | 1 | 多行洞很少 |
| 与「洞高÷行高中位」一致 | 269 / 273 = **98.5%** | 行数可信；不一致的 4 个是高洞（66–125pt） |

**4 个高洞的共同点**：投影也只切出 1 条带 ⇒ 里面墨迹是连成一片的（图/竖排/公式块），
**像素投影也切不开**。⇒ 这类不走"按洞补"，直接 `needs_review`。

**结论**：用户担心的"洞只有第一行最左点、位置不完整"不成立——洞是矩形，且 99.6% 是一行高。
真正的少数派是"高洞且墨迹连片"，那 1.5% 交给待核即可。

## 11. 接产线前的两次实测：都撞上数据/口径问题，**先不接**（2026-11-03）

### 11.1 「新旧逐洞对比」做不了：旧缓存与当前快照不是同一次运行

`data/out/物理_教材基础练 电路/ocr-page-fill.json` 里 145 条 accepted 候选，与当前
`stages.json` 的 905 个洞**零重叠**（按页、按 bbox 重叠≥50% 都查过）。`preflight` 早就标过
21 本快照过期——**这份候选是 2026-11-02 的，洞是后来的**。⇒ 「新路径多补了 182 个洞」这种话
**不能说**，两边根本不在同一批洞上。

### 11.2 洞 ↔ 行 必须 1:1，现在是多对一

新路径给 182 个洞算出了候选（273 个 content 洞里 66.7%），来源几乎全是锚点（179）。
但**同一个行文本被多个洞复用**：样例里「多维变式夯基础」重复出现多次，中位文本长度只有 4 字。
原因是判据只问"洞被这一行覆盖 ≥50%"，没问"这一行是不是已经给过别的洞"。

⇒ 直接接产线会把同一行的字填进好几个洞。**先加 1:1 约束**（一行只能落一个洞；多个洞抢同一行时，
按覆盖比例排序、其余记 `needs_review`），再谈接入。

### 11.3 结论

产线一行未改。要接，顺序是：① 先重跑一次现状（或明确放弃新旧对比）；
② 洞↔行 1:1 + 冲突记录；③ 再做三本题数回归与逐页截图审板。

## 12. 重跑现状 + 修正分配规则后的同批对比（2026-11-03）

**现状产线重跑**（`npx tsx scripts/ocr-page-fill.ts "物理_教材基础练 电路"`，花一次 OCR）：
273 个洞只有 **17 条**通过判据（6.2%）。⇒ 旧路径的覆盖率本来就很低，不是"把对的都填了"。

**分配规则修正**：实测「每个洞最多命中 1 行（217/273），但 117 行里有 47 行被 2–8 个洞碎片共用」
⇒ 1:1 会把碎片行的字丢掉。改为：**洞只认一行；一行的字按名下各洞的宽度切开分给碎片**
（`splitTextAmongHoles`，floor + 余数给宽者）。

**同批对比（现在的 stages.json，两边都在同一批洞上）**：

| 指标 | 数 |
|---|---:|
| content 洞（宽高比 ≥1.5） | 273 |
| 新路径能给出候选 | **182（66.7%）** |
| 现状产线填过 | 17（6.2%） |
| 两边都填的洞 | 19 |
| **两边字一致** | **0 / 19** |
| 跨行歧义（一个洞命中多行） | 0 |

**"0 / 19" 不是 bug**：旧路径把一整行公式塞进一个小洞（例如 p1 某洞旧值是一整条
`(1) I=q/t (2) I=U/R`），新路径只给 1 个字——两边对"这个洞该填什么"的理解根本不同。
⇒ **必须回页图抽样判定谁对**（这也是接产线前的最后一道人眼闸门）。

**一处要留意的口径**：`splitTextAmongHoles` 分的是**硬字符**（剥标点/标记后），离"可上纸面的原文"还差
一次"回填原文下标"的转换（`ocr-fill.ts` 的 `hardNorm` 带 map，可直接复用）。接产线时必须补这一步，
否则候选会丢标点与 LaTeX。

## 13. 切分两处改进：回填原文 + 切点吸附自然边界（2026-11-03 用户提，已实现）

1. **回填原文**：`hardNormWithMap()` 记录每个硬字符在原串的下标，`alignBlockLines` 返回 hard 区间
   `span`，调用方据此切**原串** ⇒ 候选不再丢标点与 LaTeX（实测候选里带标点/`$` 的比例已 >0）。
2. **切点吸附**：按洞宽定初值后，把切点挪到 ±2 字内最近的**自然边界**（标点/空白的前后）。
   实测反例：`甲乙丙丁，戊己庚辛` 按 2:1 切会在「戊|己」之间断开；吸附后落在逗号之后（`甲乙丙丁，`）。
   无标点的长串（公式串）吸不了 ⇒ 保持原切点，不硬造边界。

**仍然不做的**：不用"墨迹宽度"替 bbox 宽度（要重渲染，先记下作为后续可选项）；
不把切点吸附到"语义"层（那需要模型，与零模型原则冲突）。
