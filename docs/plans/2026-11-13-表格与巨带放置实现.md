## 0. 结论速览

- **分流策略可行（viable=true）**，但有两个必须随附的守卫与一个必须随附的放置补丁：
  1. 纯文本表 → V3 `pred_html` 结构化 HTML：3/3 结构+文字完整（**textTableRate=1.0**，口径见 §1.3）。
  2. 插图表 → 整表截图内联：5/5 整表裁图**图一个不丢**（18/18 嵌入图目视全在），文字可读（原生尺寸下）。
  3. 无边框答案索引 → 守卫跳过：墨迹横线路判据分离度极大（0.04 vs ≥0.62，§4.1）。
- **随附补丁（不可省）**：宽表裁图（原生宽 ≈890px）在手机 350px 栏宽内联缩放后正文仅 ≈8px，**不可读** ⇒
  内联 A 方案必须带「点按看原生尺寸」逃逸口（§2.3）。巨带行裁图（中位 54px）不受影响。
- **随附守卫（不可省）**：插图表判定**不能信 V3 的 img 计数**（da-p089 的 `pred_html` 与 layout 都报 0 图，
  实际 2 图）⇒ 分类必须经原卷裁图目视确认，拿不准一律走截图（无损侧，§4.2）。
- 已知缺陷（不丢内容但降保真）：含公式的纯文本表，V3 把公式 token 挪到单元格末尾（qx-p07 实测，§1.2）⇒ 列风险 + 保守开关待拍板。

### 1.1 qx-p10 丢文归因（L6：先怀疑流水线，已证实是 V3 表格模块丢文）

缺的 4 碎片在全页 `overall_ocr_res` 里：3 条精确存在（「一物块随圆盘一起」「轻绳恰好无张力时」「刚好要相对圆盘」），
第 4 条「个位于圆盘中心」以一字之差存在（rec 读成「个位于圆盘中」，line 12）。
⇒ 文字在原卷上、也被整页 OCR 读到，**只是没进 cell** ⇒ V3 HTML 路由对插图表不可靠，截图路由必要。

### 1.2 含公式纯文本表的顺序缺陷（qx-p07 实测，不丢内容但错序）

原卷：「以初速度 v₀ 做匀速直线运动」。V3 `pred_html`：「以初速度做匀速直线运动 $v_{0}$」——
公式被抽到单元格末尾；斜抛格更碎：「以 为初速度、θ为初速度与水 平方向的夹角）的速度做匀速直线运动 $v_{0x}=v_0\cos\theta(v_0$」。
文字碎片覆盖率仍 100%（故计入 textTableRate），但**阅读顺序错**。`prettifyLatex` 能把 `$...$` 排成分式/根号，
位置错不会消失。处置：列风险 R3；保守开关（含 `$` token 的 text 表也走截图）待用户拍板，默认不启用（截图代价=失去文本 selectable）。

### 1.3 textTableRate 口径与值

- 分母：kind=text-only 的表（3：qx-p02、qx-p07、da-p175），**独立于 V3 判定**（分类经真值裁图目视确认）。
- 分子：结构（行/列/格/spans/格框数）全对 **且** truth 文字碎片 0 缺失的表。
- 实测 3/3 ⇒ **textTableRate = 1.0 ≥ 0.95**。公式顺序缺陷不计入「完整性」（无丢失），单独列 R3。
- 对照：全形态 8 表 V3 直用正确率 5/8=62.5%（compare-report.json）＜95% ⇒ **不分流不可行**，分流后各路由各自达标。

## 2. 放置 A：crop 行内联裁图（巨带回退行 + 整表裁图共用同一放置器）

### 2.1 依据（S1 前全量实验，任务台账 #27）

6616 张巨带裁图：宽中位 54px；99.3% 原生适配手机 350px 栏宽；0.7% 超宽裁图缩放后行高仍 ≥19px；均 1.5KB
⇒ **A 内联**（不采用坐标框+原图链接）。本 spec 把同一放置器复用到整表裁图，但整表裁图宽度分布与巨带行裁图
完全不同（§2.3），不能直接套用「99.3% 适配」结论。

### 2.2 放置规则（native 尺寸、超栏宽才缩放）

- 裁图以**原生像素尺寸**入快照（`cropSize:[w,h]`）；渲染宽 = `min(nativeW, 可用栏宽 innerW)`，
  高按同比例（`height:auto`），**只缩不放**（放大=海报化，entry-paper.js 已有 maxFontPx 教训）。
- 位置：行级 crop 用该行 bbox 原位（`posStyle`，与 `blockNode` 同口径）；整表 crop 用表 bbox 原位。
- 裁图产出纪律（红线：判据与实现不同源 + 不丢内容）：
  `ffmpeg -vf crop=w:h:x:y` 从原卷页图裁（**禁 sips**）；裁后 ffprobe 自检尺寸恰好=w×h；**亲眼看内容**后才进快照。
  本轮 5 张整表裁图全过（附录 A）。巨带行裁图沿用 `giant-crop/crops/`（pdftoppm 产出，B-39 已目视 8 张）。
- 存放：`data/out/<doc>/table-crops/pNN-tK.png`（整表）与既有 `data/out/<doc>/giant-crop/crops/*.png`（行）。
  快照里存**相对 doc 目录**的子路径，渲染拼 `/data/out/<doc>/…`（与 `Block.img` 同约定）。

### 2.3 宽裁图可读性补丁（本轮实测，必须随附）

| 裁图 | 原生宽 | 350px 栏缩放比 | 正文原生高(rec 盒中位) | 缩放后正文高 | 内联可读？ |
|---|---|---|---|---|---|
| fulltable-qx-p03 | 894 | 0.39 | ≈20px | ≈8px | 否 |
| fulltable-qx-p05 | 892 | 0.39 | ≈20px | ≈8px | 否 |
| fulltable-qx-p10 | 895 | 0.39 | ≈20px | ≈8px | 否 |
| fulltable-da-p077 | 425 | 0.82 | ≈16px | ≈13px | 勉强 |
| fulltable-da-p089 | 378 | 0.93 | ≈15px | ≈14px | 是 |

- 判据：缩放后正文高 <10px ⇒ 内联只是「缩略图」，**必须**提供原生尺寸阅读路径。
- 设计：放置器给 crop figure 挂 `data-native-w/h`；**点按 → 原生尺寸浮层**（fixed 定位、可滚动、点背景/Esc 关）。
  浮层实现**只写一处**（reconstruct.js 内部函数，renderPaper 挂载时统一接线，与 `fitTables` 的 rAF 同模式），
  final/ 与 stages/ 零改动自动获得（纸面重建只此一处红线）。不新增 export ⇒ `reconstruct.d.ts` 不动（dts-drift 锁名字集合）。
- 巨带行裁图（中位 54px、缩放后行高 ≥19px）不触发浮层阈值，行为与 S1 实验一致。

## 3. 表格按分类渲染（三分流）

分类来源：**上游显式分类步骤**（新脚本，建议 `scripts/table-classify.ts`，本轮只读探针已验证判据可行性），
产物 `data/out/<doc>/table-v3.json`：每表 `{page, bbox, class, crop?, cropSize?, guard:{hRunW,vRunH}, source:"v3", html?}`。
`export-stages.ts` 消费它写进快照 Block 新字段（§5）。**分类不进 renderPaper**（展示层只消费快照，不做识别）。

- **text** ⇒ `Block.html = V3 pred_html`、`tableSource:"v3"`，走现有 `tableNode`（spans/colgroup/fitTables 全复用）。
  进入 text 路由的门：结构全对 + truth 碎片 0 缺（§4.3）；含 `$` 公式 token 者默认仍走 text，保守开关待拍板（R3）。
- **image** ⇒ 不写 html，写 `crop/cropSize`，走 §2 放置器整表内联。
  `appendBlockNodes` 的 `coveredByTable` 几何包含抑制**继续生效**（表框内的行块不重复画）⇒ 截图与行文字不叠影。
- **borderless** ⇒ 上游**不产出 table block**（该页行块按普通两栏文本行渲染，内容不丢）；
  renderPaper侧双保险：`tableClass==="borderless"` 的 block 即使误入快照也跳过 `tableNode` 且不进 `coveredByTable`。
  诊断模式挂灰虚线注记「无边框索引页，守卫跳过表格渲染」（默认不画，与 diagnostics 同口径）。

## 4. 守卫规则（判据全部来自原卷墨迹，独立于 V3）

灰度来源：原卷页图 → PGM（ffmpeg `format=gray -c:v pgm`，或生产 `renderGrayPage`/`parsePgm`，
`scripts/audit-hole-geometry.ts`）。阈值口径：文字/图墨 <160；**浅灰表格线 <240**（本轮实测线灰度落在 160–240 之间）。

### 4.1 G1 无边框守卫（防 V3 臆造格网）

- 判据：表区域内**最长水平连续墨迹 run / 区域宽**（`hRunW`，灰阈 240）。
  实测：8 张真表 hRunW ∈ [0.62, 1.00]；da-p186 = **0.04**（灰阈 160/200/230/240/245/250 全稳定 0.04）。
  规则：**hRunW < 0.3 ⇒ borderless**（分离裕度 0.04 vs 0.62，>15×）。
- 佐证（非主判据）：V3 格网 cols≥10 且空格率≥0.3（da-p186：17 列、447 格、空 36%）；竖 run/区域高 仅 0.14（单竖分隔线亦浅）。
- 最弱真表 qx-p10 hRunW=0.62（线最浅）⇒ 阈值 0.3 留足裕度；若未来出现更浅线真表被误杀，
  误杀方向=「不当表格渲染、行文本照常」⇒ **不丢内容**，只失格网视觉，可接受且诊断可见。
- 注意：任务简报写 27×17，**实测 pred_html 为 26 行×17 列、447 个 td、cell_box_list 447**（以实测为准）。

### 4.2 G2 插图表守卫（防「V3 说没图就没图」）

- 反例实测：da-p089 `pred_html` imgs=0 **且** layout_det_res 区域内 image 标签=0，真值 2 图 ⇒ 两个 V3 信号都不可信。
- 信号集（提议用，非决断用）：① pred_html `<img>` 数>0；② layout 区域 image 标签>0；
  ③ 独立墨迹残差：cell 内暗墨(<160) 减去「膨胀 2px 的 table_ocr rec_boxes ∪ formula dt_polys」覆盖后的残差像素。
- **本轮校准结论（如实）**：残差判据尚未干净分离——纯文本格因 rec 盒紧+抗锯齿晕圈残差可达 ≈850px
  （qx-p07 格2=851），与图格残差（da-p089 格4=798）重叠 ⇒ 残差只能做「嫌疑信号」，需连通域级校准（晕圈是 1–2px 细环、
  图是粗笔画团块；腐蚀/连通域面积可分，本轮未做完）。
- **决断规则（红线兜底）**：任一信号命中 **或** 残差嫌疑 **或** 无人目视确认 ⇒ 一律 image（截图）。
  截图是无损侧：误把 text 判 image 只失 selectable，不失内容；误把 image 判 text 丢图=红线事故。
  text 路由只发给「三信号全 0 + 残差干净 + 真值裁图目视确认无图」的表（本轮 3 张满足）。

### 4.3 G3 text 路由完整性门

- 结构（行/列/格/spans/格框数）对真值全对 **且** truth 碎片 0 缺，才许写 `tableSource:"v3"` 进 text 路由；
  任一不满足 ⇒ 降级 image 截图 + `needs_review` 标记（不静默）。qx-p10 型丢文在此门被拦（它本就含图走 image）。
- 全册推广时 truth 碎片来源=独立 rec（本地 PP-OCRv5）读整表裁图，沿用 B-41 金标链路；无笔记本时机器下界+目视抽样，口径写明。

## 5. 与 renderPaper 的接口草案（stages/reconstruct.js:637）

### 5.1 快照新增字段（Block typedef 扩展，只增不改旧字段）

```js
// stages/reconstruct.js @typedef Block 增补（JSDoc，不手写新 .d.ts 文件）：
// tableClass?: "text" | "image" | "borderless"   // 上游分类产物，展示层只消费
// tableSource?: "v3" | "mineru"                  // html 的来源旗标（默认缺省=mineru，逐字节兼容旧快照）
// crop?: string                                  // 相对 doc 目录的裁图子路径（table-crops/… 或 giant-crop/crops/…）
// cropSize?: [number, number]                    // 裁图原生像素 [w,h]
// coordSource?: "ink" | "crop"                   // 行级：B-39 旗标产出，export-stages 透传（现状：只到 align 输出，未进快照）
```

- 产出链：`ink-band-align.ts`(truncationCropFallback) → 行 `coordSource:"crop"` →
  `export-stages.ts` 透传到 block 并按 norm 框匹配 `giant-crop.pNN.json` victims 填 `crop/cropSize`；
  `table-classify.ts` → `table-v3.json` → export-stages 填 `tableClass/tableSource/html|crop`。
- 旧快照无新字段 ⇒ 所有分支缺省走现状路径（**默认关旗标逐字节不变**，与 B-39 同纪律）。

### 5.2 renderPaper / appendBlockNodes 消费分支（草案，单处实现）

```text
appendBlockNodes:
  tableBlocks = blocks.filter(kind==="table" && html && tableClass!=="borderless")   // G1 双保险
  coveredByTable 几何包含抑制：仅对「实际会渲染的表」成立（text 表与 image 表都抑制内部行；borderless 不抑制）
  block 分支：
    kind==="table" && tableClass==="image" && crop   → cropFigureNode(b)   // 整表截图内联
    kind==="table" && html（tableClass text/缺省）    → tableNode(b)       // 现状路径
    coordSource==="crop" && crop（行级）              → cropFigureNode(b)   // 巨带回退行：截图例外放置
    其余                                              → blockNode(b)       // 现状路径
cropFigureNode（内部函数，不 export）：
  posStyle 原位；img.src=/data/out/<doc>/<crop>；宽=min(cropSize[0], canvasW)；height:auto；只缩不放
  node.title = 原文本 + 「裁图例外放置（coordSource=crop / 插图表整表截图）」+ 证据路径（G1 信息不丢）
  node.dataset.coordSource / dataset.tableClass；diagnostics 时叠 bbox 审计框
  缩放后正文高<10px（cropSize 与 rec 盒中位高换算，或保守用 nativeW>innerW/0.7）⇒ 挂 data-zoom="1"
renderPaper 挂载后（rAF，与 fitTables 同模式）：
  统一给 [data-zoom] 接点按浮层（原生尺寸、可滚动、Esc/背景关）——只此一处，final/stages 零改动
```

- `coordSource:"crop"` 行的语义：**坐标回退行用截图代替文字放置**（用户已许可截图例外）；
  文本仍保留在 title 与快照（search/面板不丢），纸面呈现为裁图 ⇒ 不再出现 noBand 丢行。
  候选样式纪律：回退行是引擎原文+回退坐标，**不是 OCR 候选**，不套青绿候选框；以 `data-coord-source` 供审计区分。
- 面板 `entryCrop`（final/entry-paper.js）消费同一 block 字段：image 表/crop 行在面板里按面板宽 k 放大渲染同一裁图
  （`blockNode`/放置器共用），不另写第二份放置逻辑。

### 5.3 类型与校验

- reconstruct.js 是 DOM 类展示层：**不写 `// @ts-check`**（文件头已声明），类型由 `tsconfig.viewer.json`（checkJs+DOM lib）校验。
- 新逻辑若抽纯函数模块（如裁图缩放/zoom 阈值计算）一律 `// @ts-check`+JSDoc；**不新建手写 .d.ts**。
- `stages/reconstruct.d.ts` 属 dts-drift 锁名字集合：本草案不新增 export ⇒ .d.ts 不动；若拍板要 export 放置器供测试，
  则同步补 .d.ts 名字（DECISIONS §31 流程）。

## 6. 红线遵守清单

- 不丢内容：image 表截图 18/18 图目视全在；borderless 页行文本照常渲染；crop 行文本留 title/快照；任何拿不准 ⇒ needs_review/截图。

- 完工门：`npm run check` 全绿 + 显示层改动全量逐页截图审板（本 spec 落地时执行，本轮未改代码故不触发）。
