# 切片决策记录（DECISIONS）

垂直演进模型的两份交付物：可运行的骨架代码 + 本决策记录。
每条记录「决策 → 理由 → 状态」，是正式模块开发的直接输入。
来源：2026-08-18 外部评审结论采纳/修正后落库。

## 1. 公式指标修正：语义正确率替代可编译率

**决策**：验收指标弃用"公式可编译率 ≥95%"，改用两项：
- **公式语义正确率**：每页抽检 5~8 个公式，渲染 KaTeX 与原图人工对照判定；
- **公式召回率**：独立公式块 + 行内公式为分母（stats 已提供 `formulaBlocks` / `inlineFormulas`），
  按页记录"被当普通文本漏检"的公式数，分子=正确识别数。

**理由**：LaTeX 可编译 ≠ 语义正确。MinerU 类引擎最常见失败是静默错转
（`a^2` 变 `a_2`、上下标互换、根式错位），渲染不报错——可编译率轻松达标而题库全错。
失败形态分两类记录：**转错**（可编译但语义错）与**漏检**（压根没被当公式识别）。

**状态**：已落库（校验 UI 后续实现时须支持两种形态的分类记录）。

## 2. 回拼校验层：所有策略的强制出口

**决策**：每个切分策略的输出必须过 `validateResult`（src/validation.ts）——
题干每行与每个选项文本做**归一化包含**校验（删空白/公式标记），必须在原文块中可找回；
失败 → ReviewNote + 扣 0.3 置信度（必然落入 needs_review 区）。
对规则实现与未来 LLM 实现**同等生效**（strategy.ts 注释已写明新策略接线要求）。

**理由**：LLM 结构化输出（规则同样）会丢块、错标答案、凭空补内容。
**实现注意**：不能做字面 diff——切分剥离题号前缀、公式内联为 `$...$`、
换行与 span 拼接引入空白差异，字面比对必误报，故用去空白/去 `$` 后的子串查找。

**状态**：已落库 + 已实现（tests/validation.test.ts 4 用例）。

## 3. schema 分层冻结（修正原"最终 schema"表述）

**决策**：
- 核心骨架（Question 实体及字段）第一天冻结，演进禁止破坏性迁移；
- 扩展形态（材料题、图选项、复合题等）在真实样卷暴露缺口后**增量追加字段**，
  只做加法，不做改名/删字段。

**理由**：原"数据模型第一天就是最终 schema"表述过满——真实数据必然暴露缺口；
但"先跑样卷再冻结 schema"也不成立：没有 schema 就没有端到端链路（切片每天都靠链路活着）。
且 schema 形状由领域模型（展现层/答案开关/题库）决定，不随切分器实现变化。
正确顺序：最小骨架起步 + 样卷暴露缺口 → 中段追加字段，双向逼近。

**状态**：已落库（types.ts 头注释已更新）。

## 4. 手写答案：默认人工录入，OCR 不作链路必选项

**决策**：答案链路默认"保留原图 + 人工录入文本"，手写 OCR 作为后续增强单独评估；
切片期用手写样卷做风险冒烟，结论只回答"可行/不可行/需兜底"。

**理由**：MinerU 对手写识别弱；指望 OCR 会把答案链路变成不确定项。
**状态**：已落库。

## 6. 数据合规分级

**决策**：按数据性质分三级——
- 公开真题 → 走云 API；
- 含学生个人信息（如手写卷署名/答案纸）→ 隔离通道或本地处理；
- 自部署（PDF-Extract-Kit / MinerU 开源版，需 GPU 与维护）→ 仅作敏感通道备选，
  是否引入在拿到切片数据后决策，不作为默认方案。

**理由**：教育场景数据外发敏感，合规决策不能后补；但一刀切自部署成本过高。
**状态**：已落库（待切片期产出数据分级表）。

## 7. 双写对比验证：后置收窄

**决策**：切片期只走云 API；切片完成后，挑 2~3 页样卷跑本地开源版对比一次，
用精度差距的量级支撑"云 vs 自部署"决策。不做并行双写。

**理由**：双写=第二条链路（本地部署），塞进 2~4 周切片会摊薄聚焦度。
**状态**：已落库（后置实验项）。

本地 fallback"云主本地备"留到正式版按第 6/7 条结论决定是否需要。

**状态**：已落库（任务层实现时执行）。

## 10. 真实 API 接入观测（2026-08-18 ~ 切片完成日）

冒烟样张：`sample/23必刷题 2相互作用.pdf`（9MB 扫描版教辅，15 页，无手写）。
字段级事实（键名、响应结构、状态序列）全部实测记录于
**[docs/real-api-notes.md](real-api-notes.md)**，本节只落决策层结论，不重复细节。

### 10.1 真实结构差异（与官方文档/预期不同处）

**结论**：MinerU 云 API 实际结构与官方旧文档多处不符，客户端与 normalize 已按实测适配；
字段事实以 `docs/real-api-notes.md` 为准。

**依据**：`*_content_list.json` 顶层是 v1 扁平数组（355 条、15 页、100 图）而非 `{pdf_info}` 对象，
`pdf_info` + `page_size` 只在 `layout.json`（块字段名 `para_blocks` 系）；请求体键名为 `files[].name`
（非 fileName）；PUT 上传必须不带 Content-Type（带任意 Content-Type 即 403 SignatureDoesNotMatch）；
zip 字段是 `data.extract_result[].full_zip_url`（完成态才出现，须做存在性检查）；
业务错误一律 HTTP 200 + `code != 0`（不能只看 HTTP 状态码）。

**后续动作**：normalize.ts 已按顶层形态分流（v1 扁平 / 旧版层级）；换解析供应商时只改 normalize 层。

### 10.2 schema 缺口清单（真实样卷暴露）

**结论**：真实排版在 fixture 未覆盖处暴露两个缺口，均走「只做加法」的 schema 演进（§3）。

**依据**：① 选项被 MinerU 合并进单块——v1 常把 4 个选项拼进同一 text 块（`"A. …B. …C. …D. …"`），
规则引擎只认块首 `A.` → 每题仅收集 1 个选项；需「块内行级拆分」。
② v1 无 page_size/字号——分栏检测退化为单栏 y 序（本样张真实双栏，栏间 x0 间隙 40~110 < 页宽 28%
阈值），跨栏题号交错；需 v2 content_list / layout.json 的几何信息。

**后续动作**：块内行级拆分与分栏几何信息走 v2/layout.json 演进，作为增量字段落地，不做破坏性迁移。

### 10.3 指标基线（第一次真实跑，v1 限制下）

**结论**：题干回拼 100% 零失败、图片归属全对；选项结构化在当前 v1 下不可用（全 needs_review 主因），
选项指标挂起至 v2 或行级拆分后复测。

**依据**：切出 **83 题**（与语言层题号模式独立预测数一致）；63 条 review（47 题 ok / 36 needs_review）；
图片归属 97/97；回拼零失败；跨页重复题号噪音 82 条已修复清零（fix round 1）。
公式语义抽检未做（本扫描样本公式块仅 3 个，且 v1 无 page_size 干扰版面判断）。

**后续动作**：题干回拼/图片归属作为稳定基线；选项结构化准确率挂起至 v2 或块内行级拆分后测。

（2026-08-19 行级展开后更新）layout.json 行级接入后实测：**89 题 / 选项组 51 / review 128 / ok 82（92.1%）**。
对比 v1 基线（83 题 / 选项组 1 / review 63 / ok 47，56.6%）：选项组 **1 → 51**（达到预期 ≥30），
ok 占比 **56.6% → 92.1%**——选项结构化在真实数据上**可用**。
review 数反而上升（63 → 128），如实记录原因：
① **分栏漏检**（主因）：真实样张 15 页全部为双栏（行级粒度），但居中标题/页边注压缩了栏间最大空隙
（实测 89~159 点 = 页宽 15%~27%），仅 5 页超过 28% 阈值被正确判为两栏；行级展开后每个选项
是独立块，被误判为单栏的页按 y 序交错左右栏选项 → 产生 **103 条「选项乱序」review**。
正确判两栏的页（2/6/12/13/14）review 0~3，佐证剩余乱序全部来自分栏漏检。
② **语言层小数误判**：续行 "0.8,不计…" 之类被 `^\d{1,3}\s*[.．、)）]` 判为题号 →
4 个幽灵题号 0 题目（含 4 条相关 review）。
③ 粘连行拆分后键重启（`A.$…$B.$…$` 拆出键与当前期望不一致）→ 3 条「粘连选项键不连续」。
另注：layout 路径 normalizeLayout 只产出文本行块，未挂图片（imagesAttached 0，v1 为 97）、
无独立公式块（formulaBlocks 0，v1 为 3）——行内公式 162 处已内联。

**后续动作**：①（2026-08-19 已落地）分栏聚类（x0 桶直方图）替代 28% 阈值：真实 15/15 页正确判定双栏（此前 15 页中 10 页漏检——行级全 15 页双栏口径，旧 28% 阈值仅 5 页正确判两栏）。
回归：review 128 → 35（选项乱序 103 → 25）；ok 占比 96.6%（82/89 → 86/89，此题集「ok=直接可用」口径，非通用精度）。默认参数：bucketCount 24 / minClusterBlocks 5 / minClusterRatio 0.1 / minGapRatio 0.25。
剩余 25 条「选项乱序」构成（如实记录，未达预期 ≤5，与分栏漏检无关——15 页栏判定全部正确）：
跨栏错置 **15**（题干/选项行 x0∈[293,297]、栏界带被路由到对栏 + 整栏拼读，选项组归错题——layout.ts「按水平带归并」演进点）；语言层模式误判 **7**（q40 "0.5,…" 小数被 ARABIC_QUESTION 判为幽灵题号 0 截断跨页题题干 → 其 C/D 选项错位；q46/q58 的 "A、B、C均处于平衡…" 类题干续行以 "A、" 开头被 OPTION_LINE 当选项，占掉首个选项槽）；数据源 OCR 局限 **3**（p4 题1 选项 A/B 在源中为 interline_equation 纯公式块键前缀丢失、p14 题12 选项行内 "C.…C.…" 文本重复粘连）。② 语言层 ARABIC_QUESTION
排除小数点（`\d{1,3}\.\d` 不切题），消除 4 个幽灵题；③ ~~layout normalize 补图片/公式块挂回，
对齐 v1 的图片归属指标~~ —— **图片挂回已落地（2026-08-19）**：真实 layout.json 实测
imagesAttached **0 → 97**，与 v1 基线 97/97 对齐（95 image 块 + 2 chart 块，路径在
`blocks[].lines[].spans[].image_path`，span bbox 与块 bbox 一致）。独立公式块现状如实记录：
真实样本中公式为**行内 inline_equation span**（162 处已内联）与 3 个 `interline_equation` 块

（2026-08-20 栏目归属 + 小数守卫后）review 35 → **19**（选项乱序 25 → **10**，其中跨栏错置 15 → **0**、残乱序 10 = 同栏 A/B 选项源缺失 4 + 跨页续题 5 + 同栏图块插入 1，无一是页内跨栏连续题）；ok 占比 **97.6%（83/85）**——题总数 89 → 85（4 条幽灵题号并入真实题，分母同步减 4），ok 数 86 → 83（幽灵 4 条原计为 ok 并入，p8 题7 选项组随栏归属恢复 +1 净增），needs_review 3 → 2。

## 11. 展示层独立模块（2026-08-22）

**决策**：题目浏览器 `viewer/` 作为**独立模块**存在，与引擎 `src/` 完全解耦——
viewer/ 目录内任何文件都**不得 import 引擎 src/ 的代码**（红线写入 CONTRACT.md 与 viewer-types.d.ts 注释）。
数据来源是引擎产出的序列化形态，而非引擎运行时对象。

**契约边界**：viewer/ 只消费两样东西——
- `data/out/<docId>/questions.json`：`SegmentationResult.questions` 的 JSON 序列化（字段权威见 `src/types.ts` 的 `Question`）
- `data/out/<docId>/images/<裸文件名>`：`questions[].images[].path` 为**裸文件名**（不含路径），展示层自行拼接 `images/` 前缀

**ViewerQuestion 独立声明**：类型契约在 `viewer/viewer-types.d.ts` 以 `ViewerQuestion` 接口独立声明，
不 import 引擎 src/。引擎字段变更时须同步该文件与 CONTRACT.md，并跑 `tests/viewer-contract.test.ts`。

**两条适配规则**（CONTRACT v1，纯展示逻辑）：
① **答案拆分**：answer 若含 `\n解析：`，拆为「答案值 + 解析」两段渲染（引擎暂未拆出独立 solution 字段）。
② **图片路径**：拼接 `images/${path}`。

**留白常量**：答题区高度按题型——choice `0px` / subjective `378px`（A4 纸张 297mm → 1123px @96dpi，10cm=100mm → `1123×100/297≈378px`）；
未来 blank（填空）预留 `151px`（4cm）。该算式三处一致：viewer.css 的 `--blank-*`、tests/viewer-logic.test.ts、CONTRACT 表格。

**美学方向**：「编辑部印刷物」——纸张质感、朱砂/石青/墨色点缀、衬线标题，避免 Web 常见渐变/圆角卡片风。
浏览器验证状态：见 task-2-report / task-3-report 的 HTTP 与浏览器冒烟记录。

**数据口径（重要，如实记录）**：viewer 消费的 `data/out/<docId>/questions.json` 为
`segmentFromLayout(data/smoke/unpacked/layout.json)` 本地生成的**最新算法产物**，不是联网重新解析 MinerU、
也不是回填真实云 API 的原始输出。`data/` 目录为运行时产物、git 忽略不入库（`data/sample/` 除外）。

**状态**：已落库（TS 契约 + CONTRACT.md + viewer-contract/viewer-logic 单测 + view-server + 浏览器页面）。

## 12. viewer 体验修复 A 组（2026-08-22）

用户实测点名三个观感/可用性问题，A 组集中修复（对应 reviewer 逐状态审视记录见 [docs/design/viewer-review.md](design/viewer-review.md)）。

**① view-server 打印完整编码 URL**
`npm run view` 启动日志改为打印**带完整 doc 参数的可点击地址**（含 `%20` 空格），
避免用户复制被空格/超长截断后的 URL 导致打开空白页。

**② viewer doc 容错 effectiveDoc**
`?doc=` 参数被截断/非法/数据不存在时，viewer 不再静默空白，而是：

## 17. 渲染审计升级：从「语法零残留」到「语义级判据」（2026-10-08）

**背景**：用户对比模式截图报出两处问题——选项粘连（`A.0.20B.0.30`）与公式 A 选项
（`A.Fsin^(:)θ`）——并指出「还有很多，这个截图自反馈的迭代没有迭代好」。

**根因（两者都不是渲染器逻辑写错，而是判据太松）**：
- 选项粘连：MinerU 丢列间距，`raw[21]` 原文就是 `A.0.20B.0.30C.0.35D.0.45`（数据层无空格），
  展示层忠实显示——上游噪声，展示层可做可读性分隔。
- `Fsin^(:)θ`：MinerU 把原卷 `Fsinθ` 误读为 `F \mathrm { s i n } ^ { \mathrm { : } } \theta`
  （凭空多出上标冒号），渲染器忠实渲染了这份错误的 LaTeX。

**决策一（判据升级，根本解）**：渲染验收从「语法零残留」升为「语义级」。
旧判据只看输出有没有 `\` / `{}`，于是 `\varepsilon` → 裸名字 "varepsilon"、
`^{:}` → "(:)" 这类**语法干净但语义错误**的输出全部漏检——这正是「全量清点 0 残留」之后
用户仍一眼看到问题的原因。新增 `scripts/audit-render.mjs` 并接入 `npm run check`：
- 输出端可疑模式：`^(标点)` / `_(标点)`、残留 `\` 与 `{}`、行尾裸上下标；
- 输入端覆盖率：输入文本里的 `\命令` 是否都在渲染器已知集内——**未知命令必须在这里查，
  因为它们在输出端已被丢弃、不留痕迹**；
- 选项粘连。

**决策二（渲染器修复，`stages/latex-display.js`）**：
1. 上标语义化：数学符号（′ ∘ ∗）直出、纯标点（: . , ;）判 OCR 噪声丢弃、表达式保留 `^()`；
2. 命令表补全（`varepsilon` / `varrho` / `var*` 大写变体、`vdots` / `colon` / `oplus` 等）；
3. 最长已知前缀回退：`\thetaB` 按 `\theta` + `B` 处理——修复「未知命令整体丢弃」吞掉真实字符；
4. 未知命令丢弃命令名但保留参数内容（`\color{red}` 类连参数一并丢弃），不再裸奔命令名；
5. 裸公式判据放宽：由枚举命令名的窄表 → 含任意 `\命令`，或「字母数字 + 上下标」；
6. 选项粘连分隔（同一文本 ≥2 个标记才补空格）+ `~` 还原为普通空格。

**决策三（URL 直达）**：stages 支持 `?stage=N&page=M`，便于分享「对比模式」链接，
也让截图审计免交互取图。

**验收**：86/86 测试（新增 9 例，用例全部取自真实样张）+ 渲染审计 8 项全归零；
15 页对比截图重拍复核（第 4 页 `A.Fsinθ B. Fsin θcos θ`、第 2 页 `A.0.20 B.0.30 / C.0.35 D.0.45`）。

**流程教训**：验收判据的粒度决定漏检的粒度。「全量清点」如果清的是错的东西（语法而非语义），
全量也照样漏。判据本身要经得起「用户一眼能不能看出问题」这一检验。
