## 4. 关键事实（接手必读）

1. **坐标空间约定**（render-faithful.js）：`posStyle` 的 bbox 是 **sheet pt**（588.44×842）按百分比定位——永远正确；`px()` 是**原卷 pt**→canvas——只用于 fontSize。**两者绝不可混用**（宽度砍半 bug 的根因，已修勿回退）。
2. **origin.pdf / 原卷页图 / DOCX 是同源**：origin.pdf 页尺寸 2093×2994 = DOCX 1107×1584 × 1.89 精确——即 origin.pdf 是 DOCX 的高分渲染，不是独立印刷扫描。DOCX 字体约 19pt（实测字符宽 18.88/17.70pt），行距实测 38.3/35.0pt（**不是**旧假设 43.75）。
3. **lo_coords.json 行格式已升为 4 元组** `[text, x0, y, x1]`（x1 用于按行宽收窄），extract_lines 的解包已适配（3ce9e60），但 **align_fragments.py 未适配**——当前崩溃点 `t, x, y = cols[col][i]`。
4. **LO 匹配已 100% 命中**：108/109 文本 item 全部匹配（17/17、28/28），pos=首片段坐标可直接用（lines.json 当前为 LO_COORDS=1 版本）。
5. **图片位置精确**：lo_imgpos.json（pdfminer 提取 10 张，rId441-450），与 107 副本坐标交叉验证一致（V=971.9/1187.9 vs 972/1188）。
6. **item 文本含 @@IMG 占位符**：任何匹配键/文本对账前必须剥离，否则题干全丢（事故已发生两次：键污染、对账误报）。
7. **agent-gateway**：magpie hub 托管、已批准；正确调用=直接调 deferred 工具 `mcp__agent-gateway__ask_qoder` / `ask_codex`（DeferExecuteTool）；不要绕 magpie 的 call_tool（NoDefer）。Qoder 无法指定模型（schema: "ignored by codebuddy/qoder"），模型由 Qoder 侧配置；codex/opencode/hermes 支持 model 覆盖。
